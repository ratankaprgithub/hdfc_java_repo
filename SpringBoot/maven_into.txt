Maven Build Tool:
=================

--When developers create a Java application, they perform several activities before the application is ready for execution or release.

Typical Development Activities:
--------------------------------


1. Write source code (.java files, classes, interfaces, etc.).

2. Add external libraries (dependencies) required by the application.

Example:

    JDBC applications require a database driver JAR such as MySQL Connector/J.

3. Compile the source code.

4. Write test cases (JUnit, Mockito, etc.).

5. Add testing libraries to the project.

6. Compile and execute test cases.

7. Organize the project in a standard directory structure.


A typical Java Web Application Contents:

A Java web application may contain:

* .java
* .class
* .jar
* .html
* .css
* .js
* .xml
* Images (.jpg, .png, .gif)
* Audio/Video files (.mp3, .mp4)
* Configuration files


Packaging and Deployment:


8. Package the application as a JAR, WAR, or EAR file.
9. Deploy the packaged application to a server.

If any issue is identified, developers repeat these steps until the application is ready.


Build Process:
==============

--The process of preparing an application for execution or release is called the Build Process.

It typically includes:

* Dependency management
* Compilation
* Testing
* Packaging
* Deployment

Performing these activities manually increases the developer's effort and may lead to errors.


ANT Build Tool
--------------

--To automate the build process, Apache Foundation introduced a tool called ANT (Another Neat Tool).

Limitations of ANT:


1. ANT cannot automatically download required dependencies from the internet.
2. It does not provide built-in dependency management.
3. Developers need to write lengthy `build.xml` files.
4. Test execution and dependency handling require significant manual configuration.


Maven Build Tool:
----------------

--To overcome ANT's limitations, Apache Foundation introduced Maven.

--Maven is a Project Management and Build Automation Tool used for:

* Dependency management
* Project build automation
* Test execution
* Packaging
* Deployment

Other Build Tools

Maven
Gradle

--Both are widely used in modern Java projects.


Ways to Create Maven Projects:
------------------------------

1. Command Line (Console-Based)

Install Maven manually:

* Download Maven
* Configure environment variables
* Add Maven to the system PATH

Verify installation:

mvn -version


--After installation, Maven commands can be used to generate project templates and build applications without any IDE.


2. Using an IDE

--Popular IDEs provide built-in support for Maven.

Examples:

* IntelliJ IDEA
* Eclipse
* Spring Tool Suite (STS)

--No separate Maven installation is required in most cases.


Maven Terminology:
==================

1. Artifact

--An artifact is the output generated by a Maven project.

Examples:

* .jar
* .war
* .ear
* Compiled classes

Example:

	<artifactId>employee-management</artifactId>



--The final generated JAR/WAR is called an artifact.


2. Archetype

--An Archetype is a project template used to generate a predefined project structure.

Examples:

* Maven Quickstart Project
* Web Application Project

3. GroupId

--The GroupId uniquely identifies an organization or company.

--Naming convention is similar to a Java package name.

Examples:

	<groupId>com.hdfc</groupId>

	<groupId>com.wipro</groupId>

	<groupId>com.company.project</groupId>


4. ArtifactId:

--ArtifactId identifies a specific project within an organization.

Example:


	<artifactId>springboot-demo</artifactId>

--Usually, the project root folder name is the ArtifactId.


5. Version

--Specifies the current version of the project.

Example:

	<version>1.0.0</version>


6. pom.xml

--POM stands for Project Object Model.

--The pom.xml file contains all project-related information.

It defines:

* Project Name
* GroupId
* ArtifactId
* Version
* Packaging Type
* Dependencies
* Plugins
* Build Configuration

Example:

<project>
    <groupId>com.hdfc</groupId>
    <artifactId>springboot-demo</artifactId>
    <version>1.0.0</version>
</project>



Dependencies:


--Dependencies are external libraries required by the application.

Example:

<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>9.0.0</version>
</dependency>


--Maven automatically downloads required dependencies from repositories.


Plugins:


--Plugins extend Maven's functionality.

Examples:

* Maven Compiler Plugin
* Surefire Plugin
* Spring Boot Maven Plugin

Plugins help in:

* Compilation
* Testing
* Packaging
* Deployment


Maven Repositories:

--A repository is a storage location where Maven maintains:

* Dependencies
* Plugins
* Archetypes

--Maven repositories are of three types.


1. Central Repository

--Official Maven repository maintained by the Maven community.

	https://mvnrepository.com/

--Maven downloads dependencies from here by default.


2. Remote Repository

--Organization-specific repository used internally.

Examples:

* Nexus Repository
* Artifactory

--Used for sharing internal JARs and libraries across projects.


3. Local Repository:

--Created automatically on the developer machine.

Default location:

	~/.m2/repository


Windows Example:

	C:\Users\<username>\.m2\repository

--Whenever Maven downloads a dependency, it stores a copy in the local repository.



--Maven Standard Directory Structure


project-name
│
|-- pom.xml
│
|-- src
│   |-- main
│   │   |-- java
│   │   |-- resources
│   │
│   |-- test
│       |-- java
│       |-- resources
│
|-- target



src/main/java:

--Contains application source code.

--src/main/resources

Contains:

* properties files/YAML files
* XML files
* configuration files
* static resources



src/test/java

--Contains unit test classes.


src/test/resources

--Contains resources used by test cases.


target:

--Contains generated build artifacts.

Example:

	employee-management-1.0.jar


Maven Build Lifecycle:
----------------------

--Maven executes builds in phases.

1. validate

	mvn validate

Checks:

* Project structure
* pom.xml validity


2. compile:

	mvn compile

--Compiles source code.

	

3. test-compile

	mvn test-compile

--Compiles test classes.


4. test

--Executes unit test cases.

	mvn test


5. package

Packages the application into:

* JAR
* WAR
* EAR

	mvn package

--Generated file is stored inside the 'target' directory.

6. install

--Copies the generated artifact into the local repository (`.m2`).

	mvn install

7. deploy

--Deploys the artifact to a remote repository such as Nexus or Artifactory.

	mvn deploy

Note: Deploy does NOT upload to Maven Central automatically.

8. clean

--Deletes previously generated build files.

	mvn clean 

Note: This phase is independent of the normal build lifecycle.


Important Maven Lifecycle Rule:
-------------------------------

--If Maven executes a phase, it automatically executes all previous phases.

Examples:

mvn test

Runs:

validate
compile
test-compile
test



mvn package

Runs:

validate
compile
test-compile
test
package



mvn install

Runs:

validate
compile
test-compile
test
package
install


Configuring Java Version:
------------------------

--Older Maven projects may default to Java 1.5.

Configure Java 21 using:


<properties>
    <maven.compiler.source>21</maven.compiler.source>
    <maven.compiler.target>21</maven.compiler.target>
</properties>



--Or the modern approach:


<properties>
    <java.version>17</java.version>
</properties>


--After updating pom.xml, reload/update the Maven project.

IntelliJ IDEA:

Right Click Project
→ Maven
→ Reload/sync Project


Building a Maven Project Using command line:
--------------------------------------------

	mvn clean package

Using IntelliJ:

Maven Window
→ Lifecycle
→ clean
→ package



Quick Steps to Create a Maven Project

1. Create a Maven Project.
2. Specify:

   * GroupId
   * ArtifactId
3. Configure Java version (21).
4. Add required dependencies in `pom.xml`.
5. Reload Maven project.
6. Write application code.
7. Execute:


	mvn clean package

8. Generated JAR file will be available inside the target folder.
