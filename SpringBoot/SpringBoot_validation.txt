Exception Handling in Spring Boot application:
=============================================

Consider the following API:


@RestController
@RequestMapping("/employees")
public class EmployeeController{


	@GetMapping("/{empId}")
	public Employee getEmployee(@PathVariable Integer empId){

    		if(empId < 100){
        		throw new IllegalArgumentException("Employee Id should be greater than 100");
    		}

    		return new Employee(empId,"Rahul",500000);
	}
}


Request:

GET /wmployees/10

Output:

IllegalArgumentException

Question:

--Who catches this exception?

Answer:

--Spring Boot catches it automatically.


--Spring Boot provides a default controller called:

BasicErrorController

--which handles unhandled exceptions and generates a JSON response.


Internal Flow:
--------------

Request
   ↓
Controller
   ↓
Exception Occurred
   ↓
BasicErrorController
   ↓
JSON Error Response



{
   "timestamp":"2026-09-16T10:30:00",
   "status":500,
   "error":"Internal Server Error",
   "message":"Employee Id should be greater than 100",
   "path":"/employees/10"
}

This is the default Spring Boot behavior.



Problem with Default Response:

Suppose:

	Employee Not Found

Should return:

	404 NOT FOUND

But Spring Boot may return:

	500 INTERNAL SERVER ERROR

--if we don't handle it properly.

--This is not API-friendly.



Why Not Use Try-Catch Everywhere?
-----------------------------------

Many beginners write:

@GetMapping("/{empId}")
public Employee getEmployee(@PathVariable Integer empId){

   try{

      // business logic

   }catch(Exception e){

      // handle exception
   }
}


--This creates problems.

Imagine a Project with 200 APIs:

EmployeeController
DepartmentController
ProjectController
SalaryController
AttendanceController

Everywhere:

try{
}
catch(){
}

Code becomes:

Repetitive
Difficult to maintain
Ugly


Spring Boot Recommendation:

--Allow exceptions to propagate.
--Spring Boot will handle them.


Solution: @ExceptionHandler annotation
---------------------------------------

Spring Boot provides: @ExceptionHandler annotation

Purpose:

Catch Exception
|
Generate Custom Response

@ControllerAdvice annotation:
-----------------------------


@ControllerAdvice allows us to handle exceptions for the entire application from a single place.

--Exception handlers defined inside a class annotated with @ControllerAdvice become global handlers applicable across multiple controllers.


Without ControllerAdvice: 
-------------------------

--Each controller has its own exception handlers.

EmployeeController
     ↓
Exception Handler

DepartmentController
     ↓
Exception Handler

ProjectController
     ↓
Exception Handler



With ControllerAdvice:


EmployeeController
DepartmentController
ProjectController
AttendanceController
SalaryController
          ↓
GlobalExceptionHandler

One place.

One implementation.

Entire application covered.


--Create a class called GlobalExceptionHandler inside the "com.hdfc.exception" package.

--Define the excpetion handler method inside this class instead of defining inside the Controller class.

--Annotate this class with @ControllerAdvice annotation

Example:

GlobalExceptionHandler.java:
----------------------------

package com.hdfc.exception;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;

@ControllerAdvice
public class GlobalExceptionHandler {

	@ExceptionHandler(IllegalArgumentException.class)
	public ResponseEntity<String> handleException(IllegalArgumentException ex) {

		return ResponseEntity
				.status(HttpStatus.NOT_FOUND)
				.body(ex.getMessage());
	}
	
	
}


Whenever any controller throws:

Exception

Spring searches:

@ControllerAdvice

--and delegates exception handling to it.



Prefer Custom Exceptions:
-------------------------

Most beginners write:

throw new IllegalArgumentException();

or

throw new RuntimeException();

This works.

But it creates tight coupling.

--It is recommended to throw domain-specific custom exceptions instead of technology-specific exceptions.


Better Approach

Returning Custom Error DTO:
--------------------------

--Modify the GlobalExceptionHander.java class:


package com.hdfc.exception;

import java.time.LocalDateTime;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.context.request.WebRequest;

import com.hdfc.dto.ErrorResponseDTO;

@ControllerAdvice
public class GlobalExceptionHandler {

	@ExceptionHandler(StudentNotFoundException.class)
	public ResponseEntity<ErrorResponseDTO> handleException(StudentNotFoundException ex, WebRequest request) {

		ErrorResponseDTO errorDto = new ErrorResponseDTO(LocalDateTime.now(), ex.getMessage(), request.getDescription(false));
	
		
		return ResponseEntity
				.status(HttpStatus.NOT_FOUND)
				.body(errorDto);
	
	}
	
	
}


Final Response:

{
   "timestamp":"2026-09-16T12:30:00",

   "message": "Employee not found with id 999",

   "details": "uri=/employees/999"
}



Generic Exception Handler:
--------------------------

What if some unexpected exception occurs?

Example:

int result = 10/0;

or

NullPointerException

or

SQLException


--For this case we need to define a generic exception handler method:

Example:


package com.hdfc.exception;

import java.time.LocalDateTime;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.context.request.WebRequest;

import com.hdfc.dto.ErrorResponseDTO;

@ControllerAdvice
public class GlobalExceptionHandler {

	
	//Handle specific StudentNotFoundException
	@ExceptionHandler(StudentNotFoundException.class)
	public ResponseEntity<ErrorResponseDTO> handleException(StudentNotFoundException ex, WebRequest request) {

		ErrorResponseDTO errorDto = new ErrorResponseDTO(LocalDateTime.now(), ex.getMessage(), request.getDescription(false));
	
		
		return ResponseEntity
				.status(HttpStatus.NOT_FOUND)
				.body(errorDto);
	
	}
	
	
	//Handle generic any other types of exceptions
	@ExceptionHandler(Exception.class)
	public ResponseEntity<ErrorResponseDTO> handleOtherExceptions(Exception ex, WebRequest request) {

		ErrorResponseDTO errorDto = new ErrorResponseDTO(LocalDateTime.now(), ex.getMessage(), request.getDescription(false));
	
		
		return ResponseEntity
				.status(HttpStatus.NOT_FOUND)
				.body(errorDto);
	
	}
	
}
