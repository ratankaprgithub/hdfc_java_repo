LinkedList in Java:
===================

A Linked List is a linear data structure where elements (called node) are connected using references.

Each node contains:

1. Data
2. Address of Next Node

--------------------
| Data | Next      |
--------------------

Example:

--------------------
| 10   | Address   |
--------------------

Data: 10

Next: Address of next node



--Before Linked Lists existed, programmers mostly used Arrays.

Imagine:

int[] arr = {10, 20, 30, 40};

Looks simple.

--But suppose we want to insert 25 between 20 and 30.

--We must shift elements:

Before:
10 20 30 40

After:
10 20 25 30 40

--Several elements may need to move.

--For large datasets this becomes expensive.


Another problem with Array: 

--Imagine an array of size 100.

int[] arr = new int[100];

--But you are using only:

20 elements

Remaining: 80 spaces wasted

Memory waste.

--OR If we need to store more than 100 items then also we need to create another array.


Real World Requirement:
-----------------------

Software systems often need:

Frequent insertions
Frequent deletions
Dynamic size

Examples:

Browser history
Music playlist
Undo/Redo
Social media feeds
Task schedulers

--Arrays are not always the best choice.

--This is where Linked Lists come into the picture.


Q/- What is a Linked List?

--A Linked List is a collection of nodes connected together using references.

Unlike arrays:

Array:
10 20 30 40

all elements are stored together.

In Linked Lists:

10 -> 20 -> 30 -> 40 -> NULL

--nodes may be stored anywhere in memory.

--The only thing connecting them is the reference to the next node.



Real-time analogy:
-----------------

Imagine a train.

Engine -> Coach -> Coach -> Coach

Each coach contains:

1. Passenger information (Data)
2. Connector to the next coach (Referernce)

Similarly:

Node = Coach

Next Reference = Connector

Head = Engine

--You can travel from one coach to the next coach.

--But you cannot directly jump from coach 1 to coach 10.

--Exactly the same thing happens in Linked Lists.

Important terms in LinkedList:
------------------------------


1. Node: 

--A single element inside Linked List.


2. Head:

--The Head is a reference that points to the first node.

--Using the Head only we access the entire linked list.

Head
 |
10 -> 20 -> 30 -> NULL


Without head:

--We cannot access the list.

--Head is the entry gate to the Linked List.

--With this Head pointer only we traverse the entire Linked List.

Think of head as: The engine of a train


2. Tail:

--Tail refers to the last node.


Head
|
10 -> 20 -> 30 -> 40 -> NULL
                   |
                  Tail

--The tail node's next reference is always: NULL

--because no node exists after it.

--Tail helps perform certain operations faster.



3. Null terminator: 

-- It means "No further node exists.".

--In Singly linked list last node always points to the Null value



Example:

10 -> 20 -> 30 -> NULL

--When traversal reaches NULL: Stop

--Linked List has ended.



Array vs Linked List:
----------------------

| Feature             | Array      | Linked List    |
| ------------------- | ---------- | -------------- |
| Memory              | Contiguous | Non-Contiguous |
| Size                | Fixed      | Dynamic        |
| Insert at Beginning | O(n)       | O(1)           |
| Delete at Beginning | O(n)       | O(1)           |
| Random Access       | O(1)       | O(n)           |
| Memory Usage        | Less       | More           |
| Searching           | O(n)       | O(n)           |




Advantages Over Arrays:
-----------------------

--Dynamic resizing (add/remove nodes easily). No resizing is required.
--Efficient insertions/deletions (O(1) if position is known). just need to change the links, No Shifting required.
--No memory waste (only allocate needed nodes).

Disadvantages:
---------------

--No random access (O(n) to access nth element). i.e Must start from head and travel node-by-node.
--Extra memory for pointers.
--Since, Nodes are scattered in memory. CPU caching becomes less efficient than arrays.

--------------

Questions:
---------


Q1. Why is Linked List called a dynamic data structure?

--Because nodes are created and removed at runtime, so size can grow or shrink dynamically.

Q2. Why is random access not possible in Linked List?

--Because nodes are not stored continuously in memory and there is no indexing mechanism.

Q3. What is the role of head?

--Head stores the reference of the first node and acts as the entry point to the entire Linked List.

Q3. Why is insertion at the beginning O(1)?

--Because only a few references are updated and no traversal is required.

Q4. What happens if the Head reference is lost?

--The entire Linked List becomes inaccessible, causing all nodes to be effectively lost.

Traversing a Linked List:
--------------------------

Traversal means: Visiting every node one by one.

--Typically to process or display data, starting from the head and following the next addresses.


Example:

Head
|
10 -> 20 -> 30 -> 40 -> NULL

Output:

10
20
30
40


Traversal Analogy: Imagine a treasure hunt.
------------------

--Start at the first clue (Head).
--Read each clue (data) and follow the arrow (next address) to the next clue.
--Stop when there’s no more clues (null).


Clue1 -> Clue2 -> Clue3 -> Clue4 -> null


Traversal Algorithm:
---------------------


Step 1: Start from head.

	Node current = head;

Step2:  Keep moving until NULL.

	while(current != null)

Step3: Process current node.

	System.out.println(current.data);

Step 4: Move forward.

	current = current.next;



Code:
----

public void display() {

    Node current = head;

    while (current != null) {

        System.out.print(current.data + " -> ");

        current = current.next;
    }

    System.out.println("null");
}

--Find whether a particular value exists in the linked list or not.

	public boolean contains(int value)


Logic:

--Start from head.

--Check every node with the given value.


Code:

public boolean contains(int value) {

    Node current = head;

    while (current != null) {

        if (current.data == value) {
            return true;
        }

        current = current.next;
    }

    return false;
}



Time Complexity: O(n)

--because we may visit all nodes.





Implementing indexOf() method:
------------------------------

--Finding Position of an Element.

--Unlike arrays, a linked list does not internally maintain indexes.

--However, we can logically implement indexing by maintaining a counter while traversing the list.


public int indexOf(int value)



Logic:

Initialize an index variable with 0.
Start traversal from the head.
Compare each node's data with the given value.
If a match is found, return the current index.
Move to the next node and increment the index.
If the value is not found, return -1.




code:
-----


public int indexOf(int value) {

    int index = 0;

    Node current = head;

    while(current != null) {

        if(current.data == value) {
            return index;
        }

        current = current.next;
        index++;
    }

    return -1;
}


Time complexity: O(n)



Now, we can modify the earlier written: contains(int value) method as follows:




public boolean contains(int value) {


	return indexOf(value) != -1;

}




Insert a Node at Specific Position:
-----------------------------------

public void insertAt(int index, int value) 



Current List:

10 → 20 → 40 → 50 → NULL
		

Insert: 30

at index: 2

Expected:

10 → 20 → 30 → 40 → 50 → NULL



Important Rule:

To insert at index: i

we must reach: i - 1

Because we need access to the previous node.

--traverse the 'current' till: i-1


10 → 20 -> i -> 40 → 50

--Now to insert 30 at i:

We need to perform two link changes.


Step 1: Save old connection.

newNode.next = current.next;

30 → 40


Step 2: Connect previous node to new node.

current.next = newNode;


Result:

10 → 20 → 30 → 40 → 50


Note: If we reverse the opration then Otherwise part of the list may be lost.


Handle to edge case:


Case 1: Insert at Beginning: index == 0

insertAtFront(value);

Case 2: Insert at End: index == size

insertAtLast(value);


Case 3: Invalid Index

insertAt(-1, 10);

or

insertAt(100, 10);

--These should throw an exception.



full code:
-----------

public void insertAt(int index, int value) {

    if(index < 0 || index > size) {

        throw new IndexOutOfBoundsException("Invalid index: " + index);
    }

    if(index == 0) {

        insertAtFront(value);
        return;
    }

    if(index == size) {

        insertAtLast(value);
        return;
    }

    Node newNode = new Node(value);

    Node current = head;

    for(int i = 0; i < index - 1; i++) {

        current = current.next;
    }

    newNode.next = current.next;

    current.next = newNode;

    size++;
}


Time complexity: O(n) wrost case..

public void deleteAtLast() {

    if (head == null) {

        throw new NoSuchElementException("Linked List is empty");
    }

    if (head == tail) {

        head = null;
        tail = null;

        size--;
        return;

        current = current.next;

    tail = current;

    size--;
}

public void deleteAt(int index) {

    if (index < 0 || index >= size) {

        throw new IndexOutOfBoundsException("Invalid index: " + index);
    }

    if (index == 0) {

        deleteAtFront();
        return;
    }

    if (index == size - 1) {

        deleteAtLast();
        return;
    }

    Node current = head;

    for (int i = 0; i < index - 1; i++) {

        current = current.next;
    }

    //Reconnecting
    current.next = current.next.next;

    size--;
}



Time complexity: O(n)


Reversing a Linked List (Iterative Approach):
---------------------------------------------

public void reverse() 



Current List:

head
 |
10 → 20 → 30 → 40 → NULL
		|
	       tail
		
After reversing:

head
 |
40 → 30 → 20 → 10 → NULL
                |
	       tail


Beginner approach:
-------------------

Take all values
Store them in an array
Reverse array
Put values back


Complexity:

Time  : O(n)

Space : O(n)


Expected Solution:

--Reverse the links.

--Not the data.

Before:

head
|
10 → 20 → 30 → 40 → NULL
                |
	      tail
After:

       head
	|
NULL ← 10 ← 20 ← 30 ← 40
                      |
	             tail

Then: change the pointer

head
|
40 → 30 → 20 → 10 → NULL
               |
              tail



The Biggest Challenge:

Node prev = null;

Suppose we start with:

Original:
raj -> rohit -> sunil -> null

Reverse:


sunil -> rohit -> raj -> null

Logically equivallent to the following


null <- raj <-  rohit <-  sunil 




and we do:

current.next = prev;

Immediately.

For node 10:

10 → NULL

Now:

Where is 20?

It will be lost: The rest of the list disappears.


Rule:

Before changing a link:

--Always save the next node.

This leads to the famous: Three Pointer Technique



10 → 20 → 30 → NULL




The Three Pointers:

We use:

prev
current
next




prev: Stores previous node.

 Initially NULL

current: Node currently being processed.

 Initially head

next: Stores next node temporarily.

 Used to prevent losing the list



The Algorithm:

For every node:

Step 1: Save next node.

next = current.next;

Step 2: Reverse the link.

current.next = prev;

Step 3: Move prev forward.

prev = current;


Step 4: Move current forward.

current = next;

Repeat until:

current == null



full code:
----------

public void reverse() {


    // Edge case: if one node or empty linked list
    if(head == null || head.next == null) {

        tail = head;
        return;
    }

    

    Node prev = null;

    Node current = head;

    while(current != null) {

        Node next = current.next;

        current.next = prev;

        prev = current;

        current = next;
    }

    head = prev;
}




Time complexity: O(n)

Space complexity: O(1)

No extra data structure used.





Reversing a Linked List (Recursive Approach):
---------------------------------------------

public void reverseRecursive()



Real Life Analogy:

Imagine a line of people:

Rahul → Mohit → Aman → Karan

You tell Rahul:

"Go ask Mohit to reverse the rest of the line."

Mohit says:

"First Aman should reverse the remaining line."

Aman says:

"First Karan should handle his part."


Finally Karan says:

"I am the last person."

Now while returning back:

Karan turns Aman around
Aman turns Mohit around
Mohit turns Rahul around

--This is exactly how recursive reversal works.

Suppose:

10 → 20 → 30 → 40

We tell node 10:

Reverse everything after me.

So recursion works on:

20 → 30 → 40

Then node 20 says:

Reverse everything after me.

Now recursion works on:

30 → 40

Then node 30 says:

Reverse everything after me.

Now recursion works on:

40


Base Case: What should stop recursion?

When: Only one node remains

Example:

40 → NULL

--A single node is already reversed.


Therefore:

if(head.next == null)
{
    return head;
}


With edge case: if list is empty:

  if (head == null || head.next == null) {
        return head;
  }




Visualization of Recursive Calls:

Initial:

10 → 20 → 30 → 40

reverse(10)

    reverse(20)

        reverse(30)

            reverse(40)

Now:

40

returns.


Note: Recursive calls go to the last node.

but Actual reversal happens while returning.


The Returning Phase:

--This is where the actual reversal happens.


Returning to Node 30

Current:

30 → 40 -> null;


But we need: 

40 → 30 -> null;

Current node:

head = 30


Next node:

head.next = 40

Make:

head.next.next = head;

Meaning:

40.next = 30;

Result:

40 → 30

Now break old connection:

head.next = null;

Meaning:

30.next = null;

Result:

40 → 30 → NULL


Similarly after each recursive call this process it repeated.


The entire reversal happens because of:

head.next.next = head;

--This is the most important line.



Example:


private Node reverse(Node head) {

    if (head == null || head.next == null) {
        return head;
    }

    Node newHead = reverse(head.next);

    head.next.next = head;

    head.next = null;

    return newHead;
}



Note: we should not call reverse(head) method directly, that's way we marked it as private.

instead we need to wrap this method inside a public method.

full code:


public void reverseRecursive() {

    tail = head;

    head = reverse(head);
}


--Here before getting the new head after recursion: 

Marks the starting head as tail.

--because for the final result: tail will become head.




Time complexity: O(n)

--Each node visited once.

Space complexity: O(n)

public Node getMiddle() {

    if(head == null) {

        throw new NoSuchElementException("Linked List is empty");
    }

    Node slow = head;

    Node fast = head;

    while(fast != null && fast.next != null) {

        slow = slow.next;

        fast = fast.next.next;
    }

    return slow;
}

Floyd's Cycle Detection Algorithm:
==================================

Q/- What is a Cycle?



Normally a singly Linked List ends with: NULL

Example:

10 → 20 → 30 → 40 → NULL


But Sometimes, due to a programming bug or a special problem, a node points back to an earlier node.

Example:

10 → 20 → 30 → 40
           ↑    ↓
            ← ← ← 

Here:

40.next = 30

Now:

30 → 40 → 30 → 40 → 30 ...

The list never ends.

This is called a:

Cycle
Loop
Circular Reference


--In this kind of situation: 



public void display() {

    Node current = head;

    while(current != null) {

        System.out.print(current.data + " ");

        current = current.next;
    }
}


calling this display() method


Program never stops: Infinite Loop





Given a Linked List:

10 → 20 → 30 → 40
           ↑    ↓
            ← ← ← 

--Determine whether a cycle exists.


public boolean hasCycle()





Beginner Solution: 
------------------

--Start visiting each node.

--Store visited nodes in a HashSet.

--If element is already present inside the HashSet then cycle found: return true.

{

while(current != null) {

    if(visited.contains(current)) {
        return true;
    }

    visited.add(current);

    current = current.next;

}

Using Floyd's Cycle Detection Algorithm:
----------------------------------------


It Use:

Slow Pointer
Fast Pointer


Real Life Analogy:

--Imagine a circular running track.

--Two runners start together.

Runner 1: Turtle

Moves: 1 step

Runner 2: Rabbit

Moves: 2 steps


If they run forever on a circular track,

will Rabbit eventually catch Turtle?

YES

--No matter where Turtle is,

--Rabbit will eventually meet it.

This is the entire idea behind Floyd's Algorithm.




So, If

slow == fast

then: Cycle Exists



full code:
----------


public boolean hasCycle() {

    Node slow = head;

    Node fast = head;

    while(fast != null && fast.next != null) {

        slow = slow.next;

        fast = fast.next.next;

        if(slow == fast) {
            return true;
        }
    }

    return false;
}



Time: O(n)

Space: O(1)

No extra data structure used.



Detecting the Start of the Cycle:
---------------------------------

This is the advanced part.

Interviewers often ask:

Cycle exists.

Now find the node
where the cycle begins.


Example

10 → 20 → 30 → 40 → 50
           ↑         ↓
            ← ← ← ← ←



Cycle starts at: 30

Need to return: 30 instead of returning boolean


Amazing Floyd Trick:

--Suppose Slow and Fast meet.

At the meeting point: Keep Slow there only.

Create another pointer: start which will points to the head.

Node start = head;


Now move: both start and slow

start = start.next;
slow  = slow.next;

--One step at a time.


The point where they meet again is: Start of Cycle




Let's check:


Cycle:

10 → 20 → 30 → 40 → 50
           ↑         ↓
            ← ← ← ← ←

Suppose meeting occurs at: 40 (It can meet at 40 also)


--Now both slow and fast are at 40.

Place:

start = head

at: 10


so,

start = 10
slow = 40


Move both one step.

Step 1:

	start = 20

	slow = 50

Step 2:

	start = 30

	slow = 30


Meet again.

Answer: 30


full code:
----------


public Node findCycleStart() {

    Node slow = head;

    Node fast = head;

    while(fast != null && fast.next != null) {

        slow = slow.next;

        fast = fast.next.next;

        if(slow == fast) {

            Node start = head;

            while(start != slow) {

                start = start.next;

                slow = slow.next;
            }

            return start;
        }
    }

    return null;
}




Circular Linked List:
=====================


Until now, every Linked List we studied ended with: NULL

Example:

10 → 20 → 30 → 40 → NULL

The last node points to: NULL

--This is called a normal Singly Linked List.


In a Circular Linked List:

--Last node does NOT point to NULL.

Instead:

--Last node points back to the first node.


head           tail
 ↓              ↓     
10 → 20 → 30 → 40
↑               ↓
-----------------

tail.next = head;


This creates a circle.

Hence the name: Circular Linked List


Real Life Analogy:

--Imagine children sitting in a circle playing: Passing The Parcel


Rahul → Aman → Mohit → Karan
↑                       ↓
-------------------------


After Karan: Again Rahul

There is no: NULL

--This is exactly how a Circular Linked List behaves.


Difference Between Singly and Circular Linked List:
-----------------------------------------------------

| Singly Linked List | Circular Linked List            |
| ------------------ | ------------------------------- |
| Ends with NULL     | Never ends                      |
| tail.next = null   | tail.next = head                |
| Easy traversal     | Need special stopping condition |
| Linear structure   | Circular structure              |

Add Two Numbers Problem:
=========================

--This is one of the most famous Linked List interview problems.

It appears frequently in:

LeetCode
Amazon
Microsoft
Google
Adobe
Flipkart

and many product-based companies.


Problem Statement:

You are given two Linked Lists.

Each node contains exactly one digit:

0 to 9

The digits are stored in reverse order.

Your task is to:

Add the two numbers
and return the result as a Linked List.

The result must also be stored in:

Reverse Order



Example:
-------

Input:

List 1:

2 → 4 → 3

List 2:

5 → 6 → 4


Output:

7 → 0 → 8



Important Point:

--The numbers are stored in reverse order.

2 → 4 → 3

does NOT mean:

243

It means:

342

because:

2 = Ones Place

4 = Tens Place

3 = Hundreds Place




Similarly:

5 → 6 → 4

means:

465


Now add them:

342 + 465 = 807

Result should also be stored in reverse order:

807

becomes:

7 → 0 → 8


Think about how we add numbers in school.

Example:

  342
+ 465
------

We always start from:

Rightmost Digit

because carry is generated there.

In a Linked List:

2 → 4 → 3


the ones digit is already at the beginning.

So addition becomes easy.

No need to reverse the list.



How Humans Solve It:

Let's perform: 342 + 465

Step 1: 2 + 5 = 7

Write: 7

Carry: 0

Step 2: 4 + 6 + Carry(0)

= 10

Write: 0

Carry: 1


Step 3: 3 + 4 + Carry(1)

= 8

Write: 8

Carry: 0

Answer: 7 → 0 → 8

--Exactly the same thing we do in code.


Approach:

At every node we need:

Digit from List 1

Digit from List 2

Carry

Formula:

sum = digit1 + digit2 + carry;



Then:


Digit to Store:

digit = sum % 10;

Carry to Forward:

carry = sum / 10;


The Most Important Edge Case

Input

List1: 9 → 9 → 9

List2: 1

Meaning:

999 + 1



Iteration 1: 9 + 1

= 10

Store: 0

Carry: 1

Iteration 2: 9 + 0 + 1

= 10

Store: 0

Carry: 1

Iteration 3: 9 + 0 + 1

= 10

Store: 0

Carry: 1

Now both lists ended.

But:

carry = 1

still remains.

Therefore we must create one more node.

Result:

0 → 0 → 0 → 1

which represents:

1000




full code:
----------

public Node addTwoNumbers(Node l1, Node l2) {

    Node resultHead = null;
    Node resultTail = null;

    int carry = 0;

    while (l1 != null || l2 != null || carry != 0) {

        int sum = carry;

        if (l1 != null) {

            sum += l1.data;
            l1 = l1.next;
        }

        if (l2 != null) {

            sum += l2.data;
            l2 = l2.next;
        }

        carry = sum / 10;

        int digit = sum % 10;

        Node newNode = new Node(digit);

        if (resultHead == null) {

            resultHead = newNode;
            resultTail = newNode;
        }
        else {

            resultTail.next = newNode;

            resultTail = newNode;
        }
    }

    return resultHead;
}
