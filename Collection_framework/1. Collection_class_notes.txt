Concept:

--When array becomes full, create a new bigger array:  copy old data then add new element

      Create new array of double capacity
      Copy old elements
      Add new element


Example: Creating custom dynamic array class


MyDynamicArray.java:
---------------------

package com.hdfc;

public class MyDynamicArray {

    private int[] arr;
    private int size;

    public MyDynamicArray() {
        arr = new int[5]; // initial capacity
        size = 0;
    }

    public void add(int data) {

        if (size == arr.length) {
            System.out.println("Array is full, increasing capacity from " + arr.length + " to " + (arr.length * 2));

	    // New array with double capacity
            int[] newArr = new int[arr.length * 2];

	    // copy the data
            for (int i = 0; i < size; i++) {
                newArr[i] = arr[i];
            }

	    //changing the reference
            arr = newArr;
        }

	//adding the data
        arr[size++] = data;
    }

    public void remove(int index) {

        if (index >= size || index < 0) {
            throw new IndexOutOfBoundsException("Index out of bound");
        }

        for (int i = index; i < size - 1; i++) {
            arr[i] = arr[i + 1];
        }

        size--;
    }

    public int get(int index) {
        if (index >= size || index < 0) {
            throw new IndexOutOfBoundsException("Index out of bound");
        }

        return arr[index];
    }

    public int size() {
        return size;
    }

    public int capacity() {
        return arr.length;
    }

    public void clear() {
        size = 0;
    }

    public boolean isEmpty() {
        return size == 0;
    }

    public void display() {
        for (int i = 0; i < size; i++) {
            System.out.print(arr[i] + " ");
        }
        System.out.println();
    }
}

Collection in Java:
-------------------

--If we want to represent a group of objects as a single unit, then we use Collection.

Example:

Group of Students
Group of Employees
Group of Products

--So instead of handling objects one by one, we handle them as a single object (collection object).


Q/- What is a Framework?

--A Framework is a ready-made structure that helps developers build applications easily.

Defination:

--A framework is a ready-made, reusable, semi-implemented architecture that provides common functionality. Developers just plug in their specific code where needed.

Real-life Example:

Think of a car, the manufacturer provides the engine, chassis, wheels, and structure (framework). You only need to drive it (your business logic).


So,

Framework reduces developer work.


--Before Collection Framework, Developers need to code Data Structures themselves like:

Array
Stack

Searching

--The Collection Framework reduces developer effort by providing ready-made implementations of common data structures.




Collection Framework:

--Collection Framework contains classes and interfaces that help us store and manage a group of objects.

--Each collection class is like a container or bag that can hold multiple objects.

--It provides ready-made Data Structures.

limitations of Iterator:
----------------------

1. By using Iterator we can always move forward direction, but can't move backward direction, it is a single direction cursor.

2. By using the Iterator we can perform only read and remove operation, but we can't perform the replace and add operation.




ListIterator interface:

--By using ListIterator we can move either to the forward direction or to the backward direction. It is a bi-directional cursor.

--By using ListIterator we can also perform replace or add operation while iterating over the List elements.

Note: ListIterator is the most powerfull cursor but its limitation is, It is not a universal cursor, we can use it only with List objects not with the Set or Queue objects.

Polymorphic References for Creating ArrayList Object:
==================================================


--In Java, we can create an ArrayList object in multiple ways using different reference types. 
--This is possible due to polymorphism (an object of a child class can be referred by its parent type).

--Here are the common styles:

1. Using Object class reference: (Least recommended for collection usage)

	Object obj = new ArrayList<String>();

--You can only call methods of the Object class (like toString(), equals(), hashCode()) without downcasting.

--Not useful for collection operations.


2. Using Collection interface reference:

	Collection<String> col = new ArrayList<>();


--You can only call methods declared in the Collection interface (without downcasting).

--This reference can point to any implementation of Collection (ArrayList, LinkedList, HashSet, etc.).


3. Using List interface reference : Most Recommended & Widely Used

	List<String> list = new ArrayList<>();

--You can call all methods declared in the List interface (add(), get(), set(), remove(int), indexOf(), etc.).

--This is the best practice in most cases because:

--It promotes loose coupling (your code is not tied to a specific implementation).

--You can easily change the implementation later (e.g., from ArrayList to LinkedList or Vector) without changing the rest of the code.

--It clearly shows that you only need List behavior.


4. Using ArrayList class reference (Concrete type)


	ArrayList<String> al = new ArrayList<>();


--You can call all methods: Object + Iterable + Collection + List + ArrayList-specific methods (ensureCapacity(), trimToSize(), clone()).

--Use this only when you specifically need ArrayList-only methods (like ensureCapacity() or trimToSize()).

--It makes your code tightly coupled to ArrayList, which reduces flexibility.



Best Practice:

-- Always prefer 
	List<String> list = new ArrayList<>(); 

--unless you have a strong reason to use the concrete ArrayList type.

--Programming to the interface (List) makes your code more maintainable and flexible.

--If you declare the reference as List, you cannot call ensureCapacity() or trimToSize() directly. You will need to downcast or use ArrayList reference.

Purpose: Converts an array (or varargs) into a fixed-size List.

Key Characteristics:

--Returns a fixed-size list backed by the original array.

--You can modify existing elements using set(index, value).
--You cannot change the size: add(), remove(), clear() method, throw UnsupportedOperationException.
--Allows null values.

--Changes made to the original array are reflected in the list (and vice versa) because it's just a wrapper/view of the array.



Syntax:
-------

List<T> list = Arrays.asList(element1, element2, ...);   // varargs

// or

List<T> list = Arrays.asList(array);   // from existing array


Example:


Demo.java:
---------


package com.hdfc;

import java.util.Arrays;
import java.util.List;

public class Demo {

	public static void main(String[] args) {

		List<String> cities = Arrays.asList("Delhi", "Mumbai", "Chennai", "Kolkata");

		System.out.println("List: " + cities);
		System.out.println("Size: " + cities.size());

		// Allowed: Modify element using set()
		//cities.set(1, "Hyderabad");
		//System.out.println("After set(1, 'Hyderabad'): " + cities);

		// Not Allowed: Changing size
		// cities.add("Bangalore"); // UnsupportedOperationException
		// cities.remove(0); // UnsupportedOperationException

		// Backed by array - changes reflect both ways
		String[] arr = { "Apple", "Banana", "Mango" };
		List<String> fruits = Arrays.asList(arr);
		arr[0] = "Guava"; // Change in array
		System.out.println("After changing array: " + fruits); // [Guava, Banana, Mango]

	}

}




2. List.of() :
----------

Interface: java.util.List (static factory method)
Introduced: Java 9
Purpose: Creates an immutable (unmodifiable) list with the given elements(array or varargs). 


Key Characteristics:

--Returns a completely immutable list.

--You cannot modify elements (set()), add, or remove anything, All structural modification methods throw UnsupportedOperationException.

--Does NOT allow null values (throws NullPointerException if any element is null).

--Creates a copy of the elements (not backed by the original array).

--More memory-efficient and slightly better performance for small immutable lists.

--Thread-safe (since immutable).



Syntax:
------

List<T> list = List.of(element1, element2, element3, ...);


List<T> list = List.of(array);   // from existing array



Example:
---------

List<String> cities = List.of("Delhi", "Mumbai", "Chennai", "Kolkata");

System.out.println("Immutable List: " + cities);

// All modifications throw UnsupportedOperationException
// cities.set(1, "Hyderabad");     // Exception
// cities.add("Bangalore");        // Exception
// cities.remove(0);               // Exception

// Null not allowed
// List.of("Delhi", null, "Mumbai");  // NullPointerException


String[] arr = { "Apple", "Banana", "Mango" };
		
List<String> list = List.of(arr);
		
		
arr[0] = "Guava"; // Change in array
System.out.println("After changing array: " + list); // Not changed. // [Apple, Banana, Mango]


If you need a modifiable list (you want to add/remove later), always do:


List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C"));
// or
List<String> list = new ArrayList<>(List.of("A", "B", "C"));




--Arrays.asList():  Fixed size but mutable elements
--List.of(): Fully immutable list





Difference between Arrays.asList() and List.of()
-------------------------------------------------


| Feature      	| Arrays.asList() 	| List.of()  |
| ------------ 	| --------------- 	| ---------  |
| Add/Remove   	|  No            	|  No        |
| Modify (set) 	|  Yes           	|  No        |
| Null allowed 	|  Yes           	|  No        |
| Type         	| Fixed-size      	| Immutable  |

package com.hdfc;

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class Demo {

	public static void main(String[] args) {

		List<String> list = new ArrayList<>();

		list.add("Apple");
		list.add("Banana");
		list.add("Mango");
		list.add("Orange");
		list.add("Grapes");
		System.out.println("Initial List: " + list);

		// 1.insert at specific position
		list.add(2, "Cherry");
		System.out.println("After add(2, 'Cherry'): " + list);

		// 2. Get the element from the specific index
		System.out.println("Element at index 3: " + list.get(3));

		// 3. Replace the old element
		String old = list.set(4, "Pineapple");
		System.out.println("set(4, 'Pineapple') - Old value was: " + old);
		System.out.println("After set(): " + list);

		// 4. removes by index and returns the removed element
		String removed = list.remove(1);
		System.out.println("remove(1) returned: " + removed);
		System.out.println("After remove by index: " + list);

		// 5. index of First and last occurrence of an object
		list.add("Apple");
		System.out.println("List now: " + list);
		System.out.println("First occurrence of 'Apple': " + list.indexOf("Apple"));
		System.out.println("Last occurrence of 'Apple': " + list.lastIndexOf("Apple"));

		// 6. subList(int fromIndex, int toIndex)  view of portion of list
		List<String> sub = list.subList(1, 4); // from index 1 to 3 (toIndex exclusive)
		System.out.println("subList(1,4): " + sub);

		// Modifying subList also affects original list and vice-varsa (because it's a view)
		sub.set(0, "Guava");
		System.out.println("After modifying subList, original list: " + list);

	}

}




Time Complexity of various methods of Collection and List interface:
====================================================================

add(E e) : O(1) amortized : May become O(n) during resizing.

add(index, e): O(n): shift elements

remove(Object o) : O(n): Need to search the element.

remove(index): O(n): Shift elements

contains(Object o): O(n): linear search

addAll(Collection c): O(n): Depends on size of input

removeAll(Collection c): O(n * m): worst case

retainAll(Collection c): O(n * m): comparison required

get(index): O(1)

set(index, e): O(1)

indexOf(): O(n): Linear serach

lastIndexOf(): O(n): Reverse serach

package com.hdfc;

import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;

public class Demo {

	public static void main(String[] args) {

		Scanner sc = new Scanner(System.in);
		List<String> list = new ArrayList<>();

		while (true) {

			System.out.println("\n===== MENU =====");
			System.out.println("1. Add a Product Name");
			System.out.println("2. Remove Product");
			System.out.println("3. Display Product list");
			System.out.println("4. Search a Product");
			System.out.println("5. Exit");
			System.out.print("Enter your choice: ");

			int choice = sc.nextInt();

			switch (choice) {

			case 1: {
				System.out.print("Enter product name to add: ");
				String product = sc.next();
				list.add(product);
				System.out.println("Product added successfully!");
				break;
			}

			case 2: {
				System.out.print("Enter Product name to remove: ");
				String product = sc.next();

				if (list.remove(product)) {
					System.out.println("Product removed successfully!");
				} else {
					System.out.println("Product not found!");
				}
				break;
			}

			case 3: {
				System.out.println("All Products: " + list);
				break;
			}

			case 4: {
				System.out.print("Enter Product name to search: ");
				String product = sc.next();

				if (list.contains(product)) {
					System.out.println("Product found!");
				} else {
					System.out.println("Product not found!");
				}
				break;
			}

			case 5: {
				System.out.println("Exiting program...");
				sc.close();
				return; //Proper exit
				//System.exit(0);
			}

			default:
				System.out.println("Invalid choice! Try again.");
			}
		}
	}
}

Generice revisted:
==================

--Generics are a powerful feature introduced in Java 5 (1.5) that allows you to write reusable, type-safe classes, interface and methods that can work with different data types.

--Generics let us to write true polymorphic code that works with any data types.

--Think of generics as placeholders for types(<T>, <E>, <K, V>, etc.).Instead of writing separate classes or methods for String, Integer, Employee, etc., you write one generic version of  class/method that works with any type you specify at uses time.


Note: Generics work only with reference types (objects like String, Integer, Employee). Primitives (int, double) are not allowed directly. You must use wrapper classes (Integer, Double, etc.).



--Generics provide compile-time type safety, not runtime safety (due to type erasure).


Without Generics (pre-Java 5 style):

--You had to use Object and do manual casting. This was error-prone and not type-safe.



Example: Creating a Java class which will work with any type of Object.(Non-Generic class)

-----------

public class MyGen {

	
	private Object obj;
	
	void add(Object obj) {
		this.obj = obj;
	}
	
	
	Object get() {
		return obj;
	}
	
}

--Here eventhough MyGen class can accept any type of object but, to get back that object we need to perform downcasting.

	private T obj;
	
	void add(T obj) {
		this.obj = obj;
	}
	
	
	T get() {
		return obj;
	}
	
}



--Now the above MyGen class is capable to manage any type of object

----------------------

1. Type Safety

--Compiler prevents you from adding wrong types (e.g., you can't add a String to List<Integer>).

2. No More Downcasting / ClassCastException

--You get the exact type back without casting.

3. Code Reusability

--Write once, use with any type.

4. Compile-time Bug Detection

--Errors are caught early instead of at runtime.

5. Cleaner and More Readable Code

--To make our Collection to work as a covarience type and make them flexible, we need to make use of wildcards:

--With the collections we can use following 3 types of wildcards:


1. Subtype or upper bound wildcards: Covariance (for reading/producing)

2. SuperType or Lower bound wildcards: Contravariance (for writing/consuming)

3. Unbounded Wildcard 
 

PECS Principle (Producer Extends, Consumer Super)

--Producer (you only get/read values) : Use ? extends T
--Consumer (you only put/write values):  Use ? super T






1. Subtype or upper bound wildcards: (? extends T)
-------------------------------------




--Using this we can achieve the covarinece type of feature in collections also.

syntax:

<? extends T> 

--means a type that is either T or a child of T, 


Example:


public static void printArray(List<? extends Employee> employees){

	for(Employee employee: employees){
		System.out.println(employee);
	}
	// employees.add(new Employee());       // Compile error - cannot add
	employees.add(null); // allowed
}


--This method can accept at max or upper bound of Employee class object. we are trying to restrict the boundry at max to Employee class

--The wildcard type ? extends Employee indicates some unknown subtype of Employee. we can call this method with List<Developer> or List<Manager> as well.


Note: When we are using Subtype or Upper bound Wildcard, we can't add a new element/object inside the collection. For example inside the above method, if we try to add an object of Employee or its subtype we get a compilation error.


--The reason is, the ? inside "? extends Employee", could refer to any subclass, perhaps Developer or Manager, Since we can't add a Developer to a List<Manager>.

--But we can add null value, because null is the default value of any reference variable.

2. SuperType or Lower bound wildcards:
-----------------------------------

--Contravarience is the opposite of covarience, and it refers to the ability of a type to accept more generic(broader) types.

--Contravariance allows a generic type to work with its supertypes using ? super.

--Lower bounded wildcard (? super T) allows a generic type to accept T and its supertypes, making it suitable for write operations.

syntax:

<? super T> 

Means:

Accepts:

T
Parent of T
Grandparent of T













Note: We can specify an upper bound for a windcard, or we can specify a lower bound but we can not specify both.




--Suppose, we want to write a method that puts Integer object into a list, To maximize flexibility, we would like that method to work on List<Integer>, List<Number> or List<Object>: Anything that can hold an Integer value.



public static void addNumbers(List<? super Integer> list){

	for(int i=1;i<=10;i++){
		list.add(i); //Perform write operation
	}

}



List<Integer> l1 = new ArrayList<>();
List<Number> l2 = new ArrayList<>();
List<Object> l3 = new ArrayList<>();

List<String> l4 = new ArrayList<>():



addNumbers(l1); //valid
addNumbers(l2); //valid
addNumbers(l3); //valid

addNumbers(l4); //invalid




Key properties:
--------------


List<? super Integer>


1. Write (Allowed)

list.add(10); // Integer allowed, Because all these lists can store Integer

--You can ADD T and its subclasses
--You CANNOT safely add superclasses


2. Read (Restricted):

Object obj = list.get(0); // Only Object allowed, because Compiler doesn't know exact type
// Not able to read in the lower bound types.

Unbounded wildcard:
-------------------

syntax:

List<?>


--In Java Generics, a wildcard (?) represents an unknown type.

--Unbounded Wildcard (?) means:  "any type"

--Unbounded wildcard is used when you don’t care about the type of the elements, but still want type safety.

--There are two scenarios where using unbounded wildcard is useful.

1. When writing a method that relies on Object class functionality, If a method uses only methods defined in the Object class (like toString(), equals()), then the exact type is not important.

2. If a method uses operations that do not depend on the generic type (such as size(), clear(), isEmpty()), then <?> can be used.


List<?> means a list typed to an unknown type. This could be a List<A>, a List<B>, a List<String> etc.

Since  you do not know what type the List is typed to, you can only read from the collection but can not add the data, and you can only treat the objects read as being Object instances. Here is an example:

package com.masai;

import java.util.Arrays;
import java.util.List;

public class Demo{

	public static void fun1(List<?> list) {
		
		for(Object obj:list) {
			System.out.println(obj.toString());
		}
		//here we can not write inside the list
		//list.add(10); // error	
	
	}

	public static void fun2(List<?> list) {
		
		 System.out.println("Size: " + list.size()); // no type needed
        	 list.clear(); // no type needed

		// list.add(list.get(0)); //Not allowed
	
	}

	
	
	public static void main(String[] args) {
		
		List<Integer> ilist=Arrays.asList(10, 11);
		
		List<String> slist= Arrays.asList("A","B","C");
		
		fun1(ilist);
		fun1(slist); 
		
		fun2(slist); 

				
		
	}

}
 



Difference between List<?> and List<T>
--------------------------------------

List<?>:

--The method says:  "I don’t know what type this list holds".
--You cannot use the type specifically:  use only as Object type.
--Give me any list, I don’t care what’s inside.



Example:

public static void fun2(List<?> list) {

    // T value = list.get(0);  // Not allowed

    Object value = list.get(0); //  Only Object allowed

  //list.add(list.get(0)); // Not allowed	
  //list.add("Hello"); //Not allowed

  list.add(null); // allowed
	
}



List<T>: 

--The method knows the exact type (even if you don’t see it explicitly)
--That type can be used inside the method
--Give me a list of some specific type, and I’ll work with that type.




Example:

public static <T> void fun1(List<T> list) {

    T value = list.get(0);   // Allowed

  list.add(list.get(0)); //Allowed

}



--Here T is not fixed globally, Its value will be decided at method call time:

fun1(List<String>)  :  T = String  
fun1(List<Integer>)  : T = Integer



Example:


public static <T> T getFirstElement(List<T> list) {

    T value = list.get(0);   

     return value;
   
}







Example: Swap Elements in List(any type of Element)

public static <T> void swap(List<T> list, int i, int j) {
    T temp = list.get(i);
    list.set(i, list.get(j));
    list.set(j, temp);
}



Note: We cannot perform this operation with List<?> because the compiler does not know the exact type, so methods like set() are not type-safe.

Type Erasure in Java:
---------------------

--Type Erasure is a mechanism used by Java to implement generics.

--Type Erasure means removing generic type information at compile time.


Defination:
-----------

--Type Erasure is the process of removing generic type information at compile time so that generic code is converted into non-generic code for JVM execution.

Need for Type Erasure:
---------------------

--Java introduced generics in Java 5 without changing JVM

So:

--JVM does not understand generics
--Compiler converts generic code to normal code
-- No Generic Information at Runtime:


This ensures:

--Backward compatibility with older Java versions


How Type Erasure Works:
---------------------

Case 1: Unbounded Type

class Box<T> {
    T value;
}


After compilation:

class Box {
    Object value;
}


Case 2: Bounded Type:

class Box<T extends Number> {
    T value;
}

After compilation:

class Box {
    Number value;
}



Example:

List<String> list = new ArrayList<>();
list.add("Hello");

After type erasure:

List list = new ArrayList();
list.add("Hello");



Key Effects of Type Erasure:
-------------------------


1. Method Overloading Restriction


void fun1(List<Integer> list) {
		
}
	
void fun1(List<String> list) {
		
} // Not allowed


2. Type Casting Inserted by Compiler

List<String> slist = List.of("Java", "Pyhton", "C++");

String s = slist.get(0);
	
Compiler internally adds:

String s = (String) list.get(0);


Important Note

--Generics provide compile-time type safety, not runtime safety.



Gift Box Analogy:

At compile time:  box has label (String, Integer)
At runtime: label removed:  only box remains
