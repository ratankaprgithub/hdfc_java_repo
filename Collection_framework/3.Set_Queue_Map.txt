Set in Java:
============

--Set is a child interface of the Collection interface.

--It represents a collection that does not allow duplicate elements.

--Index concept is not applicable in Set. Therefore, we cannot use methods like get(int index).

--If we try to add a duplicate element, the add() method simply returns false (no exception is thrown).

--Set is mainly used when uniqueness of elements is required.


Key Features of Set:
---------------------

--No duplicates allowed.

--Insertion order is not preserved (in most implementations).

--Does not support index-based access.
x
--Set does not define any extra methods other than Iterable and Collection interfaces.


Main Implementation classes of Set:
-----------------------------------

HashSet (Most commonly used)
LinkedHashSet
TreeSet (SortedSet)


HashSet Class:
--------------


--HashSet is the first and most popular implementation of the Set interface.

--It is not synchronized (not thread-safe by default).

--It does not maintain insertion order.

--Elements are stored and retrieved based on their hashCode()  (Hashing mechanism).

--It offers excellent performance for searching (contains()), add(), and remove() operations: average time complexity O(1).

--HashSet also does not have any extra methods.


Note: Internally, HashSet uses HashMap to store elements. The element itself is stored as a key in the HashMap, and a dummy object is used as the value.



Use HashSet when:

1. You need unique elements
2. Fast lookup required
3. Order does not matter



Constructors:
------------


HashSet hs1 = new HashSet<>(); // Default: capacity 16, load factor 0.75
HashSet hs2 = new HashSet<>(int initialCapacity);
HashSet hs3 = new HashSet<>(int initialCapacity, float loadFactor);
HashSet hs4 = new HashSet<>(Collection c);   // Copy any types of Collection


Load Factor (Fill Ratio):
------------------------

--Default value is 0.75.

--When the HashSet is 75% full, A new internal array (table) is created and elements are rehashed.

HashSet<Integer> hs= new HashSet<>(1000,0.8f);

--here initial capacity is 1000 and and once reaches to the 80% then A new internal array(buckets) is created and elements are rehashed.




Important Points:
-----------------

--Duplicate elements are not allowed.

--Adding duplicate returns false.

--Only one null value is allowed.

--Best choice when frequent searching is required. searching a perticular element based on hashCode will have time complexity O(1).

--Iteration order is unpredictable (not based on insertion order).

    }

Important Notes:
-----------------

1. HashSet is backed by HashMap: add() internally calls map.put(element, PRESENT).

2. Performance: Excellent for add, remove, and contains operations (Average O(1), worst-case O(n) due to collisions).

3. Not suitable when you need to maintain insertion order: Use LinkedHashSet.

4. Not suitable when you need sorted elements: Use TreeSet.

5. Not thread-safe by default. Use Collections.synchronizedSet(new HashSet<>()) if needed.




HashSet Internal working:
------------------------

--HashSet does not store data directly using array index like ArrayList.

--Instead, it uses:

1. Buckets
2. Hashing
3. equals()
4. hashCode()


Analogy:

--Suppose a college has 16 lockers.

--Each student gets locker number based on Roll Number:

	locker = rollNumber % 16

--So students are distributed quickly.

--Same concept is used in HashSet.


Internally, HashSet uses: HashMap

When we write:

	HashSet<String> hs = new HashSet<>();

Internally Java creates:

	HashMap<String, Object> 


Where:

Your element = Key
Dummy constant object = Value


Example:

{
   "Delhi" = PRESENT,
   "Mumbai" = PRESENT,
   "Chennai" = PRESENT
}



Internal Code Concept
---------------------
Roughly:


public class HashSet<E> {

    private HashMap<E,Object> map;

    private static final Object PRESENT = new Object(); //dummy object

    public boolean add(E e){
        return map.put(e, PRESENT) == null;
    }
}



--In HashMap, internally buckets of size 16 is created.

--the bucket system is internally based on an array (table), default size 16, and each array index acts as one bucket. where Java places elements based on hash values.

How Duplicate is Checked: 

Suppose:

hs.add(25);
hs.add(25); // not added 



Internal Steps:
---------------

hashCode = 25

Important Rule:
--------------

--For duplicate detection:

Java uses BOTH:

hashCode()
equals()


Search Operation:  contains() method: hs.contains(41);

Internal Working: 

Step 1:

hashCode = 41
index = 9


Step 2:

Only bucket 9 searched.

--Not entire set.

--That is why searching is fast.


Why O(1) Average Time?

--Because Java directly jumps to bucket.

Instead of checking:

25, 41, 57, 99, 110 ...

--It directly checks correct bucket.

So average: O(1)


Worst Case O(n): 

--If all elements go same bucket:

Bucket 9:

10 -> 20 -> 30 -> 40 -> 50 -> 60

Then search becomes linear using equals() method: O(n)

--In modern Java versions, if collisions become too many, linked list converts into balanced tree.

So performance improves to: O(log n)



Advance concept:
---------------

--In modern Java HashMap / HashSet (since Java 8), a bucket’s collision chain (linked list) may be converted into a balanced tree (red-black tree) when certain thresholds are met.

Main Threshold: 

--When the number of nodes in a single bucket becomes 8 or more, Java considers treeification.

--This constant is internally:

	TREEIFY_THRESHOLD = 8

So if one bucket has:

	A -> B -> C -> D -> E -> F -> G -> H

--then it can convert from linked list to tree.

But There Is One More Important Condition: 


--The overall table (internal array) size must be at least 64.

	MIN_TREEIFY_CAPACITY = 64

--If table size is smaller than 64, Java usually prefers resizing the table instead of converting to tree.

So:

Bucket chain reaches 8 nodes AND table capacity >= 64

--Then linked list can become balanced tree.


Because: If capacity is small (like 16 or 32), resizing often spreads elements into new buckets and reduces collisions naturally.

--That is cheaper than building a tree.


Untreeify Threshold: 

--If a tree bucket later shrinks to 6 or fewer nodes, Java may convert it back to linked list.

UNTREEIFY_THRESHOLD = 6



How null is Handled in HashSet (Internal Working)

null is allowed in a Java HashSet, but only one null value can be stored because duplicates are not allowed.

Example:

HashSet<String> hs = new HashSet<>();

hs.add(null);   // true
hs.add(null);   // false


Internal Reason:

HashSet uses HashMap internally.

Conceptually:

	map.put(null, PRESENT);

--So null is stored as a key in internal HashMap.

But null.hashCode() Causes NullPointerException

--So Java HashSet and HashMap handles null specially.

Special Rule for null:

--Inside HashMap, if key is null, Java directly assigns:

hash = 0

--So null always maps to bucket related to hash 0.

--So null usually goes into:

bucket 0





Benchmark Lookup vs Iteration:
==============================


What is Benchmarking?

--Benchmarking is the process of measuring the execution time or performance of different operations to compare their efficiency.

In Java, performance is commonly measured using:

System.nanoTime()

--This method returns the current time in nanoseconds, making it suitable for measuring short execution durations.


Lookup:
-------

--A lookup operation checks whether an element exists in a collection.

Example:

list.contains(100);
set.contains(100);

Time Complexity:
-----------------

| Collection | Lookup Complexity |
| ---------- | ----------------- |
| ArrayList  | O(n)              |
| LinkedList | O(n)              |
| HashSet    | O(1) Average      |
| TreeSet    | O(log n)          |



--HashSet is significantly faster for search operations because it uses a hash table internally.


Iteration:
----------

--Iteration means visiting every element in a collection.

Example:

for(Integer value : list){
    System.out.println(value);
}

--Both ArrayList and HashSet require visiting each element once.


Time Complexity:
----------------

| Collection | Iteration Complexity |
| ---------- | -------------------- |
| ArrayList  | O(n)                 |
| HashSet    | O(n)                 |


--Although both are O(n), ArrayList often has better cache locality and can be slightly faster in practice.

LinkedHashSet:
=============


--LinkedHashSet is a child class of HashSet and an implementation of the Set interface.

It is similar to HashSet but with one major difference:

--It maintains the insertion order of elements.

--While HashSet does not guarantee any order, LinkedHashSet preserves the sequence in which elements were added.

--It is the best choice when you need uniqueness + insertion order.




Internal Working:
-----------------

--LinkedHashSet internally uses a LinkedHashMap.

--Additionally, it maintains a doubly-linked list running through all its entries.

--This linked list is responsible for maintaining the insertion order.



--Performance is slightly slower than HashSet due to the extra overhead of maintaining the linked list.

--Supports fast operations: add(), remove(), contains():  average O(1) time complexity.

5. Returns the second non-repeating character from a string.


Input:  "swiss"
Output: 'i'


 public static char secondNonRepeating(String str)




Solution:
---------


 public static char secondNonRepeating(String str) {

        LinkedHashSet<Character> unique = new LinkedHashSet<>();

        HashSet<Character> duplicate = new HashSet<>();

	char[] chr = str.toCharArray();

        for(char ch : chr) {

            if(duplicate.contains(ch) == false && unique.contains(ch) == false) {
                unique.add(ch);
            }
            else {
                unique.remove(ch);
                duplicate.add(ch);
            }
        }

        int count = 0;

        for(char ch : unique) {
            count++;

            if(count == 2)
                return ch;
        }

        return '\0';
    }




6. Remove duplicate characters from string while keeping the last occurrence of each character.


Input:  "abacabad"
Output: "cbad"


Logic:

--Traverse string from right to left.

--Use HashSet to track visited chars.

--Use StringBuilder.


public static String keepLastOccurrence(String str)



Solution:
---------


 public static String keepLastOccurrence(String str) {

        HashSet<Character> set = new HashSet<>();

        StringBuilder sb = new StringBuilder();

        for(int i = str.length()-1; i >= 0; i--) {

            char ch = str.charAt(i);

            if(set.contains(ch) == false) {
                set.add(ch);
                sb.append(ch);
            }
        }

        return sb.reverse().toString();
    }










TreeSet class:
==============


--TreeSet class is the another implementation of Set interface.

Hierarchy:

Iterable
   |
Collection
   |
  Set
   |
SortedSet
   |
NavigableSet (provides powerful navigation methods)
   |
TreeSet


--Insertion order is not preserved.

--It stores elements in sorted order (either natural sorting order or custom sorting order).

--Duplicates are not allowed.

--It is implemented using a Red-Black Tree (a self-balancing binary search tree).

--Even a single Null value is also not allowed: because comparisons are required. Adding null usually throws NullPointerException.



Best Choice When:

--You want elements in sorted order.

--You need fast retrieval of first/last elements or range-based operations.




Time Complexity:
----------------

add(), remove(), contains(): O(log n) time complexity.




Constructors:
-------------

TreeSet<E> ts1 = new TreeSet<>();  // Natural ordering
TreeSet<E> ts2 = new TreeSet<>(Comparator<? super E> c); // Custom sorting using Comparator
TreeSet<E> ts3 = new TreeSet<>(Collection<? extends E> c);
TreeSet<E> ts4 = new TreeSet<>(SortedSet<E> s);

Comparable<T> interface:
=====================

--This interface belongs to java.lang package.

--By using this interface, we will specify the sorting rules/technique inside the class.

--This interface is having only one abstract method:

	public int compareTo(T);

--if we try to add any class object inside the TreeSet, then that class must implement Comparable interface and override this compareTo method. And inside this method we need to specify the sorting logic of that class object.




Example:

--TreeSet class internally call this compareTo() method to sort the elements.

currentObject.compareTo(obj2):-

returns -ve when currentObject has to place before obj2: obj2 >greter than currentObject

returns +ve when currentObject has to place after obj2. obj2 <less than currentObject.

return 0 when currentObject and obj2 both are equal.

Note: incase of equal, TreeSet consider the duplicate object, and it will not allow that object.






Example:

Student.java:
------------

package com.hdfc;

public class Student implements Comparable<Student> {
    private int roll;
    private String name;
    private int marks;


    //Default constructor
    public Student() {
     
    }


    //Parameterized construction
    public Student(int roll, String name, int marks) {
        this.roll = roll;
        this.name = name;
        this.marks = marks;
    }

    //Getters and Setters

    @Override
    public int compareTo(Student s2) {

	Student s1= this;
	
	if(s1.marks > s2.marks)
		return +1;
	else if(s1.marks < s2.marks)
		return -1;
	else
		return 0;

	//return Integer.compare(s1.marks, s2.marks);
	

    }

    @Override
    public String toString() {
        return "Student [roll=" + roll + ", name=" + name + ", marks=" + marks + "]";
    }
}





--The above sorting logic is based on the marks.

Various implementation of Comparator and their effect:
======================================================


import java.util.Comparator;

public class MyComparable implements Comparator<Integer> {
    
    @Override
    public int compare(Integer x, Integer y) {
        if (x < y) {
            return +1;  // x is placed after y
        } else if (x > y) {
            return -1;  // x is placed before y
        } else {
            return 0;   // x and y are treated as duplicates
        }
    }
}


--When adding elements to a TreeSet (e.g., inserting 10, 0, 15, 4, 10), the return value of the compare() method strictly dictates how the tree is built.

Here is how different return statements affect the final output:


1. return x.compareTo(y): Natural Sorting Order: Standard ascending order. Duplicates are removed: [0, 4, 10, 15]

2. return -x.compareTo(y); (or y.compareTo(x)): Descending Order: Reverse of natural sorting. Duplicates are removed.[15, 10, 4, 0]

3. return +1; Insertion Order: Every new element is treated as "greater than" the existing elements. Duplicates are allowed because 0 is never returned. [10, 0, 15, 4, 10]

4. return -1; Reverse Insertion Order: Every new element is treated as "less than" the existing elements. Duplicates are allowed because 0 is never returned. [10, 4, 15, 0, 10]

5. return 0; First Element Only: Every new element is treated as an exact duplicate of the first element. Only the first element is added; the rest are rejected. [10]


Important Note:  While returning a constant +1 or -1 only allows a TreeSet to store duplicates and preserve insertion/reverse-insertion order, it effectively breaks the rules of a mathematical Set and turns the underlying Red-Black Tree into a skewed, unbalanced LinkedList.




Difference between Comparable and Comparator:
=============================================

| Feature               | Comparable   | Comparator    |
| --------------------- | ------------ | ------------- |
| Package               | java.lang    | java.util     |
| Method                | compareTo()  | compare()     |
| Sorting defined       | Inside class | Outside class |
| No. of sorting logics | One          | Multiple      |
| Modification needed   | Yes          | No            |




Note: Comparable provides the default (natural) sorting order inside the class, whereas Comparator allows us to override that order and define custom sorting from outside the class.

PriorityQueue class:
====================

--PriorityQueue is an implementation of the Queue interface, but it behaves differently from a standard FIFO (First-In-First-Out) queue.

--Elements are processed according to priority.

Analogy: 

--An Emergency Room in Hospital. Even if a patient with a "sore throat" arrives first, a patient with a "heart attack" will be processed immediately because their priority is higher.


Default priority: (Min Heap)

--By default, it acts as a Min-Heap, meaning the smallest element is at the "head" and will be removed first. 

For the Custom class: class must implements the Comparable interface.

--Elements are processed according to their natural ordering or by a Comparator provided at queue construction time.


Key Features:

-- Ordering: Not FIFO. Elements are ordered based on priority.
-- Nulls: Does not allow null elements (throws NullPointerException).
-- Duplicates: Allows duplicate elements.
-- Performance: - offer() and poll(): O(log n)
-- peek(): O(1)


Constructors:
-------------

1. PriorityQueue<Integer> pq = new PriorityQueue<>(); //default capacity is 11

--So internally Java creates space for 11 elements initially.

--When the internal array becomes full, PriorityQueue automatically grows.

--The growth is: 

If current capacity < 64

Grow by approximately:

newCapacity = oldCapacity + (oldCapacity + 2)

Which is roughly:

--about 2x + small adjustment

If current capacity >= 64

Grow by:

newCapacity = oldCapacity + (oldCapacity / 2)

Which means: 1.5 times


2. PriorityQueue<Integer> pq = new PriorityQueue<>(100); with initial capacity 100


3. PriorityQueue pq= new PriorityQueue<>(Comparator);


Internal Mechanics: The Binary Heap:
------------------


--Internally, PriorityQueue is implemented using a Binary Heap (a complete binary tree).

-- A Min-Heap is a complete binary tree. where the parent node is always smaller than or equal to its children.

Note: The min-heap only guarantees that the smallest element is at the root (index 0). It does not maintain a fully sorted list in memory. It only "sorts" the necessary elements when you call poll().

--In a PriorityQueue, elements are not stored in fully sorted order like a TreeSet.
Therefore, when we print the PriorityQueue object directly or traverse it using an Iterator, the elements may not appear in the expected sorted sequence.

--This is because PriorityQueue internally uses a heap structure, not a sorted tree.

--However, the element at the head of the queue always follows the defined priority (minimum by default, maximum if custom comparator is used).

So, when we access elements using methods like:

peek()
poll()
remove()
element()

--the returned head element will always be in correct priority order.

So, PriorityQueue looks unsorted when printed, but removal using poll() gives elements in sorted priority order.




Heap:
-----

--A Heap is a special tree-based data structure that follows a rule called the Heap Property.

--It is mainly used when we need to repeatedly access:

Smallest element quickly
or
Largest element quickly


--A Heap is always a Complete Binary Tree, meaning:

1. All levels are completely filled, except possibly the last level.

2. The last level is filled from left to right.


--Although Heap looks like a tree, it is usually stored internally inside an array using the following formula:

Left child index: (2 * i) + 1
Right child index: (2 * i) + 2

Parent node: (i-1) / 2


So:

	Heap = Complete Binary Tree + Array Representation


Heap is useful when we repeatedly need:

--Highest priority item
--Lowest price product
--Most urgent patient
--Next shortest path node
--Largest score


Types of Heap:
--------------

--There are two main types:

1. Min-Heap
2. Max-Heap



1. Min-Heap:
------------

--In a Min-Heap, the value of the root node must be the minimum among all its children. This same property must be recursively true for all sub-trees.

Root Element: Always the smallest element in the entire heap.

Relationship: Parent Node <= Child Nodes.

Example


       10 (Root - Smallest)
      /  \
    20    30
   /  \
  40   50


Explanation:

10 <= 20 and 30
20 <= 40 and 50

So this is a valid Min-Heap.


Array representation:
-----------------------


Stored Level-by-Level in Array:

[10, 20, 30, 40, 50]

Index Position:

Index : 0   1   2   3   4
Value :10  20  30  40  50


Verification Using Formula:
---------------------------

For index 0: value 10

Left child  = (2*0)+1 = 1:  20
Right child = (2*0)+2 = 2: 30


For index 1: value 20

Left child  = (2*1)+1 = 3:  40
Right child = (2*1)+2 = 4: 50


For index 2: value 30

Left child  = 5 (not present)
Right child = 6 (not present)


Hence proved:

[10,20,30,40,50] correctly represents the tree.




Use Case: This is the default internal structure for Java's PriorityQueue. When you call poll(), it removes the root, giving you the smallest value.



Max-Heap:
---------

--In a Max-Heap, the value of the root node must be the maximum among all its children. This property must hold true for every node in the tree.

Root Element: Always the largest element in the entire heap.

Relationship: Parent Node >= Child Nodes.


	50 (Root - Largest)
      /  \
    40    30
   /  \
  10   20



Array representation:

[50,40,30,10,20]



Use Case: Used when you want to prioritize the "highest" values (e.g., a leaderboard or a task queue where the highest ID gets processed first).



To convert into the max heap:

PriorityQueue<Integer> pq = new PriorityQueue<>(Comparator.reverseOrder())





PriorityQueue Methods:
---------------------

add(e) / offer(e): Inserts an element into the priority queue.

peek()	Retrieves, but does not remove, the head (smallest element). Returns null if empty.

poll()	Retrieves and removes the head (smallest element). Returns null if empty.

remove(object)	Removes a specific element from the queue.

Deque interface:
================

--Deque (pronounced "Deck") stands for Double-Ended Queue.

--It is a sub-interface of the Queue interface.

--Unlike a standard Queue, a Deque allows you to insert and remove elements from both ends (front and rear).

--It is a special data structure in which elements can be:

Inserted from front
Inserted from rear
Removed from front
Removed from rear

--So it works from both ends.

--Because of Two-Way Processing, It can function as both a FIFO (First-In-First-Out) Queue and a LIFO (Last-In-First-Out) Stack.

--It is more flexible than a simple Queue because: 

Normal Queue allows:

Insert rear
Remove front

But Deque allows:

Insert front / rear
Remove front / rear

So Deque is more powerful than Queue.

1. Train Coach Door

Passengers can enter from:

Front gate
Back gate

--And can also leave from both sides.


2. Parking Lane Open from Both Ends

--Cars can enter or exit from either side.

Question 6: Reverse First 3 Elements of Queue

Input:

10 20 30 40 50

Output:

30 20 10 40 50



Logic:
------

Step 1: Dequeue (remove) the first 3 elements from the Queue and push them onto a Stack(Using ArrayDeque).

Step 2: Pop the elements from the Stack(ArrayDeque) and enqueue (add) them back to the rear of the Queue.

Step 3: Now the first 3 elements are at the back and reversed. To get them back to the front in the correct order, dequeue the remaining elements (the ones that weren't reversed) and move them to the back of the queue.





Solution:
---------

import java.util.*;
public class Demo {
    public static void main(String[] args) {

        Queue<Integer> q = new ArrayDeque<>();

        q.offer(10);
        q.offer(20);
        q.offer(30);
        q.offer(40);
        q.offer(50);

        Deque<Integer> st = new ArrayDeque<>();

	//moving 1st 3 elements from Q to Stack
        for(int i=1;i<=3;i++)
            st.push(q.poll());


        while(!st.isEmpty())
            q.offer(st.pop());

	int rem = q.size() - 3;

        for(int i=1;i<=rem;i++)
            q.offer(q.poll());

        System.out.println(q);
    }
}

Map Interface:
==============


--The Map interface is part of Java Collections Framework and is used when we need to store data in the form of key-value pairs.

--Here key and value must be an object (Primitives are not allowed).

--Each key is unique (duplicate keys are not allowed).

--Values can be duplicated.

--Every key-value pair is called an Entry.

--Map is not a child interface of the Collection interface. It is a separate root-level interface.



Example:


(101, Raj)
(102, Simran)
(103, Aman)



Think of it like:

Dictionary: word -> meaning
Phonebook: name -> number
Student Roll No -> Student Name
Locker Number -> Owner Name
Word -> Its frequency




Main Purpose: To quickly retrieve a value based on its key (very fast lookup using hashing in most implementations).




Important methods of the Map<K,V> interface:
--------------------------------------------




1. V put(K key, V value):

--Inserts a key-value pair. If the key already exists, replaces the old value with the new one and returns the old value. 
--Returns null if the key was not present.
--This method can be used for update the value also


2. V get(K key);

--Returns the value associated with the key, or null if the key is not found.


3. boolean containsKey(K key);

--Check whether the Map contains the specified key object or not.


4. boolean containsValue(V value);

--Check whether the Map contains the specified Value object or not.


5. boolean isEmpty();

--Checks if the map has no key-value pairs.


6. int size();

--Returns the number of key-value pairs (entries) in the map.


7. V remove(K key);

--Removes the entry for the specified key and returns the value. Returns null if key not found.


8. Set<K> keySet();

--Returns a Set containing all the keys.


9. Collection<V> values();

--Returns a Collection containing all the values.


10. Set<Map.Entry<K,V>> entrySet()

--Returns a Set of all entries (key-value pairs).




Note: Map revolve around two basic operations:


V put(K key,V value); //To store/insert/update

and 

V get(K key); //To retrieve



Entry interface:
----------------

--Each key value pair is called as one entry, hence a map is considered as a group of entries.


--Without existing Map obj there is no-chance of existing entry obj (because of this Entry interface is defined inside Map interface).

HashMap class:
==============


--The HashMap class is the most commonly used implementation of the Map interface. It uses a hash table data structure internally to store the data, which makes it incredibly fast for basic operations.


Feature of HashMap class:
-------------------------


--Stores data in (Key, Value) pairs.

--It uses a technique called Hashing to determine where to store the data.

--Does not preserve the insertion order, It does not guarantee any order of elements. The order of entries can even change over time.

--It allows one null key and multiple null values.

--It is non-synchronized (not thread-safe). If multiple threads access it simultaneously, it must be synchronized externally by using Collections.synchronizedMap() method.

--Provides O(1) (constant time) performance for basic operations like get() and put().



How HashMap Works Internally:
-----------------------------


--HashMap works on the principle of Hashing. It uses an inner class called Node<K, V> (which implements Map.Entry) to store data.

1. The Buckets (Array)

--HashMap is essentially an array of "buckets." When you provide a key, Java calculates its HashCode to determine which bucket the entry should go into.

2. Hash Collision

--If two different keys result in the same bucket index, it is called a collision.

Before Java 8: HashMap handled collisions using a LinkedList. New entries were added to the end of the list at that bucket.

Java 8 and later: If a bucket exceeds a certain threshold (8 entries), The bucket chain may be converted into a red-black tree based node structure. This improves performance from O(n) to O(log n) for search within that bucket.


Already discussed in HashSet.

3. HashMap<Integer, String> hm = new HashMap<>(int initialCapacity, float loadFactor); 


4. HashMap<Integer, String> hm = new HashMap<>(Map map); // Create a HashMap containing elements of the specified Map.

LinkedHashMap class:
====================


--The LinkedHashMap is a subclass of HashMap. 

--It is almost identical to HashMap in terms of performance and functionality, with one major difference: 

--It preserves the insertion order of key-value pairs. That means entries are stored in the same sequence in which they were inserted.


Characteristics:


--It is a combination of a hash table and a Doubly Linked List.

--It preserves the insertion order. If you put "Delhi" then "Mumbai", they will always come out in that order when you iterate.

--Slightly slower than HashMap because it has the added overhead of maintaining the linked list, but it still offers O(1) for add, contains, and remove.


Example:


LinkedMapDemo.java:
-------------------


package com.hdfc;
import java.util.LinkedHashMap;
import java.util.Map;

public class LinkedMapDemo {
    public static void main(String[] args) {
        // Insertion Order is preserved
        Map<String, String> lhm = new LinkedHashMap<>();

        lhm.put("Z", "Zebra");
        lhm.put("A", "Apple");
        lhm.put("M", "Mango");

        System.out.println(lhm); 
        // Output: {Z=Zebra, A=Apple, M=Mango} (Exactly as inserted)
        
        // HashMap would likely print: {A=Apple, Z=Zebra, M=Mango}
    }
}



When to Use LinkedHashMap?
=========================

Use when:

Key-value pairs needed
Fast lookup needed
Order should remain same
Predictable iteration required

            "car","ball","sky","mango"
        };

        HashMap<Integer,
            ArrayList<String>> map =
                new HashMap<>();

Question:

Array contains numbers from 1 to 5, but one number is missing.

{1,2,4,5}

Solution:
----------

import java.util.HashMap;

public class Demo {

    public static void main(String[] args) {

        int[] arr = {1,2,4,5};
        int n = 5;

        HashMap<Integer,Integer> map =
                new HashMap<>();

        for(int num : arr)
            map.put(num,1);

        for(int i=1;i<=n;i++) {

            if(!map.containsKey(i)) {
                System.out.println(i);
                break;
            }
        }
    }
}





TreeMap class:
==============


--TreeMap is a class in Java is the another implementation class of the Map interface.

Hierarchy:
----------


Map(I)
 |
SortedMap(I)
 |
NavigableMap(I)
  |
TreeMap(C)



--It also stores data in the form of key-value pair, just like HashMap, but with one special feature:

It stores all keys in sorted order automatically.


Analogy:

Imagine a dictionary.

Words are stored alphabetically:

Apple
Ball
Cat
Dog
Elephant

If words were random, searching becomes difficult.

Same concept in TreeMap.

--Keys are automatically arranged in sorted order.


Example:

101 -> Raj
103 -> Aman
102 -> Simran
105 -> Priya
104 -> Rahul


When stored inside TreeMap, output becomes:

101=Raj
102=Simran
103=Aman
104=Rahul
105=Priya

Sorted by key.


Because internally it uses a: Red-Black Tree

--which is a self-balancing binary search tree.

So:

Tree + Map = TreeMap


Features of TreeMap:
====================

--Stores data in key-value pairs

--Duplicate keys not allowed

--Duplicate values allowed

--Keys remain sorted automatically

--Faster than normal tree traversal

--Null key not allowed( throws NullPointerException)

--Multiple null values allowed

--Not synchronized

Time complexity:

put() = O(log n)
get() = O(log n)
remove() = O(log n)


Example:

===========


--Hashtable is similar to HashMap, but with the following important differences:


| HashMap                                                                    | Hashtable                                                                         |
| -------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Introduced in Java 1.2 as part of the Collections Framework.               | Available since Java 1.0 (legacy class).                                          |

WeakHashMap class:
==================


--WeakHashMap is a special implementation of the Map interface.

--It works similar to HashMap, but with one important difference:

--Keys in WeakHashMap are stored as weak references.

That means:

--If a key object has no strong reference outside the map,
--then it becomes eligible for Garbage Collection (GC),
--and the corresponding entry may be removed automatically.


Simple Meaning:

HashMap:

--Map keeps key alive.

--Even if outside references are gone, key remains because map strongly references it.

WeakHashMap:

--Map does NOT strongly protect key.

--If no outside strong reference exists, GC can remove key + entry.


Key Rule: 

--If key loses all strong references,
--WeakHashMap entry can disappear.



Example 1: Unreferenced Keys



Demo.java:
----------

import java.util.WeakHashMap;

public class Demo {

    public static void main(String[] args) throws Exception {

        WeakHashMap<Employee,Integer> map = new WeakHashMap<>();

        map.put(new Employee(10,"Raj",50000),100);
        map.put(new Employee(20,"Aman",60000),200);

        System.out.println(map.size()); // 2
        System.out.println(map);

        System.gc();
        Thread.sleep(1000);

        System.out.println(map.size());
        System.out.println(map);
    }
}


Possible Output:

2
{...two entries...}
0
{}


Because keys were created like:

new Employee(...)

No reference variable saved.

So keys became eligible for GC.

IdentityHashMap:
================

--IdentityHashMap is a special implementation of the Map interface.

--It is similar to HashMap, but with one major difference:

--It compares keys using reference equality (==), not logical equality using equals().



Normal HashMap Behavior:
-----------------------

--HashMap checks duplicate keys using:

hashCode() + equals()

--That means two different objects containing same data may be treated as same key.


IdentityHashMap Behavior:
--------------------------

--IdentityHashMap checks keys using:

key1 == key2

That means:

Same object reference: same key
Different objects, even same content: different keys


Example: Using HashMap

HashMap<String,Integer> map = new HashMap<>();

map.put("one",10);
map.put(new String("one"),40);

System.out.println(map.size());
System.out.println(map);


Output:
1
{one=40}


Example: Using IdentityHashMap:


import java.util.IdentityHashMap;

        IdentityHashMap<String,Integer> map = new IdentityHashMap<>();

        System.out.println(map.size());
        System.out.println(map);
    }
}

2
{one=10, one=40}
