TypeScript:
===========

--TypeScript (TS) is a superset of JavaScript.

This means:

Valid JavaScript + Extra Features = TypeScript

--Every JavaScript program is also a valid TypeScript program.

--TypeScript was developed and is maintained by Microsoft. It was first released in 2012.


In JavaScript, variables can change their datatype at runtime.

Example:

let age = 25;

age = "Twenty Five";   // Allowed

--No error occurs during coding.

The error is discovered only while running the application.

--For small applications this is manageable.

--For large enterprise applications:

Banking Applications
Insurance Applications
E-Commerce Platforms
ERP Systems

runtime errors become costly.

--TypeScript solves this problem using:

Static Type Checking
let age:number = 25;

age = "Twenty Five";    // Error

--Error is detected during compilation itself.




How TypeScript Works?
=====================

--Browser understands only JavaScript.

--Browser cannot execute TypeScript directly.

--So TypeScript code must be converted into JavaScript.

This process is called:

Transpilation:



TypeScript Code (.ts)
          |
          |
         TSC
(TypeScript Compiler)
          |
          |
JavaScript Code (.js)
          |
          |
       Browser / NodeJS

--TypeScript compiler generates clean JavaScript code


TypeScript Compiler:
---------------------

TypeScript compiler command:

	tsc filename.ts

Example:

	tsc app.ts

Generated file:

	app.js


Install TypeScript:

	npm install -g typescript

Step 3: Verify Installation

	tsc -v


JavaScript vs TypeScript:
=========================

| JavaScript                     | TypeScript                                      |
| ------------------------------ | ----------------------------------------------- |
| Dynamically Typed              | Statically Typed                                |
| Errors found at Runtime        | Errors found at Compile Time                    |
| Runs directly in Browser       | Needs compilation                               |
| Suitable for small/medium apps | Suitable for large applications                 |
| ES6 Features                   | ES6 + Interfaces + Generics + Advanced Features |

Access Modifiers
=================

TypeScript supports:

public
private
protected

Unlike JavaScript.



--These modifiers we can apply on:

properties/variables
methods/functions inside the class
constructors

Modifiers are not applicable to:

class/interface
interface members 
standalone functions





1. Public
----------

--Default access modifier.

--Accessible everywhere.

Example:

class Employee{

    public name:string;

}

or simply

class Employee{

    name:string;

}

Both are same.


Usage:

	let e = new Employee();

	e.name="Ratan";

Allowed.


2. Private:
-----------

Accessible only inside the same class.

Example:

class Employee{

    private salary:number;

}

Usage:

	let e = new Employee();

	e.salary = 50000;

Compiler Error.

--Private members increase encapsulation.


3. Protected:
-------------

Accessible:

Inside class
Inside child classes

Not accessible outside.

Example:

class Employee{

    protected name:string;

}



Most common style:


class Employee{

    constructor(private id:number,private name:string,private salary:number){

    }

    show(){

        console.log(this.name);

    }

}

Note: The method overriding rules are almost the same as Java:

compatible parameters,

Upcasting in TypeScript (Same as Java)
=======================================

Java:

Animal a = new Dog();

TypeScript:

class Animal{

    speak(){
        console.log("Animal Sound");
    }

}

class Dog extends Animal{

    bark(){
        console.log("Bow Bow");
    }

}

let a:Animal = new Dog();


Here:

let a:Animal = new Dog();

is upcasting.

The reference type is Animal.

The object type is Dog.



Dynamic Method Dispatch: It is also same as Java:
------------------------

ava:

Animal a = new Dog();

a.speak();

If Dog overrides speak(), Dog's version executes.

Same in TypeScript.

Example:

class Animal{

    speak(){
        console.log("Animal Sound");
    }

}

class Dog extends Animal{

    speak(){
        console.log("Dog Barking");
    }

}

let a:Animal = new Dog();

a.speak();

Output:

Dog Barking

The method selected depends on the actual object (Dog), not the reference type (Animal).

This is runtime polymorphism / dynamic dispatch.




Downcasting in TypeScript: Similar to Java:
--------------------------

Java:

Animal a = new Dog();

Dog d = (Dog)a;

TypeScript equivalent:

let a:Animal = new Dog();

let d = a as Dog;

or

let d = <Dog>a;

Both are valid.

--This is called Type Assertion.


Safe Downcasting:
-------------------

Java:

if(a instanceof Dog){
    Dog d = (Dog)a;
}


TypeScript:

if(a instanceof Dog){

    let d = a as Dog;

    d.bark();

}

--This is the recommended approach.


Interface in TypeScript:
========================


--Why Do We Need Interfaces in TypeScript?

Suppose we have a function:

function greet(user:any){

    console.log("Hello " + user.name);

}

Problem:

greet({firstName:"Ratan"});


Output:

	Hello undefined

Runtime issue.


--We want a contract that says:

Any object passed to greet()
must contain a name property.

--This is where Interfaces help.


An Interface defines a contract.

Syntax:

interface User{

    name:string;

}


Now,

function greet(user:User){

    console.log("Hello " + user.name);

}

Valid:

	greet({name:"Ratan"});

Invalid:

	greet({firstName:"Ratan"});

Compiler Error.


Important Difference from Java:
===============================

Java:

class Customer
implements User

--must explicitly implement the interface.

TypeScript:

No need.

--If the object contains the required properties, it automatically satisfies the interface.

This is called:

	Structural Typing


Example:


interface User{
    name:string;
    age: number;
}


function showUser(user:User):void{

    console.log("User name :",user.name);
    console.log("User Age: ",user.age);
}


showUser({name: "Raj",age: 25});
//showUser({name:"Raj"}); //ERROR

Module System in JavaScript / TypeScript:
=========================================

--A module is simply a file that contains related code:

Variables
Functions
Classes
Interfaces
Types
etc.


--which can be shared with other files.


Example:


employee.ts:

    console.log("Hello");
}

--Another file may need this function.

--Instead of rewriting the code, we can export and import it.


Without modules:
-----------------

--All code in one file

--As applications grow, keeping all code in a single file becomes difficult.

Problems:

Difficult to maintain
Difficult to debug
Code duplication
Naming conflicts
Poor team collaboration

--To solve these problems, applications are divided into multiple files called Modules.

With modules:

employee.ts
student.ts
product.ts
order.ts

--Each file has its own responsibility.

Export Keyword:
---------------

--The export keyword makes a member available outside the current module.

We can export:

Variables
Functions
Classes
Interfaces
Type Aliases


Exporting Variables:

	export const PI = 3.14;


Exporting Functions:

export function add(a:number,b:number):number{
    return a+b;
}



Exporting Classes:

export class Employee {

    constructor(public id:number,public name:string){
    }

}




Exporting Interfaces:


export interface User {

    id:number;
    name:string;

}



Import Keyword:
----------------

--The import keyword is used to access exported members from another module.


1. Import Specific Members:

import { add, multiply } from "./math.js";

console.log(add(10,20));
console.log(multiply(10,20));


2. Import Single Member:

	import { add } from "./math.js";


3. Import All Members:

import * as MathUtil from "./math.js";

console.log(MathUtil.add(10,20));
console.log(MathUtil.multiply(10,20));

===============

--When multiple members are exported individually, they are called Named Exports.

CommonJS Module System (Old Node.js):
=====================================

--Before ES Modules, Node.js used CommonJS.

--CommonJS is the older module system used by Node.js before ES Modules were introduced.

---------

    return a+b;
}

--require() is a CommonJS function used to load another module.

Example:

Meaning:

--Load the math module and return whatever is exported from that file.

Think of it as:

"Bring the exported content of another file into this file."
