Functional Programming in Java: 
===============================

--Functional programming is a programming style where functions can be:

1. Stored in variables 
2. Passed as arguments of a method.
3. Returned from a method.


From Java 8, Java supports functional programming using:

--Functional Interface
--Lambda Expression (It is simmilar to arrow function in Java-Script language.)
--Method Reference
--Stream API

--To make code shorter, cleaner, and more readable.



Functional Interface:
----------------------

--In Java, the functional interface is the base for the functional programming.


--A Functional Interface is an interface that contains only one abstract method.

It can have:

One abstract method

Multiple default methods
Multiple static methods
Multiple private instance methods
Multiple private static methods
Methods from Object class



Example1:

@FunctionalInterface // optional annotation for the functional interface
interface MyInterface {
    void show();   // Only one abstract method
}





Example2: Error (Not a functional interface)


@FunctionalInterface
interface MyInterface {
    void show1();
    void show2();   
}


Because: 2 abstract methods are there.


Example3:


@FunctionalInterface 
interface MyInterface {

    void show(); //abstract method

    public default void show2(){
	//default method
    }   

   public static void show3(){
	//static method
    }   

    private void show4(){
	//private instance method
    }   

    private static void show5(){
	//private static method
    }   


   public String toString(); //Method of Object class
   public boolean equals(Object obj);
   public int hashCode();



}



--The above interface is the valid functional interface.



Advantages:

Less boilerplate code
Better readability
Easier behavior customization
Supports Stream API
Encourages declarative programming

Lambda expression:
-----------------

--It is an expression used to implement functional interface in shorter way.




Example Without Lambda:
-----------------------

    }

Here also less code, but still long approach.



Using Lambda expression:
------------------------


Syntax:

(parameters) -> { body }


Example:
-------

MyInterface obj = () -> {
    System.out.println("Hello");
};

obj.show();


Even shorter:

MyInterface obj = () -> System.out.println("Hello");
obj.show();



Note: To use the Annonymous inner class, interface need not be a functional. but to use Lambda Expression, interface must be functional.



Rules to use Lambda Expression:
------------------------------

--Lambda Expression is a implementation of a functional interface (using Lambda Expression we can provide the implementation of a Functional Interface in much more easier way).

--Lambda Expression comprises 3 things:

1. Parameter (here data type is optional and parameter name also can be any name) : If only one parameter is there then () small bracket is also optional.

--Small bracket () is mandatory when we have zero or more than one parameter is there.

2. Lambda operator  ->

3. Method body: If we write only one statement inside the implementation body then {} is optional and "return" keyword is not allowed.



Note:- A lambda expression matches only the method signature (parameter list + return type).

--The abstract method name is irrelevant..



Note: A Lambda Expression does NOT create a new method.

--It provides the implementation of the single abstract method of a Functional Interface.



Target Typing:
-------------

--Java determines the type of a lambda expression from the context where it is used.


Example1:


@FunctionalInterface
interface Greeting {
    void sayHello();
}

Now:


Greeting g = () -> System.out.println("Hello");

Java sees:

Greeting g =


--and immediately understands:

--This lambda must implement sayHello()

--because Greeting has only one abstract method.

--And it matches with the signature of sayHello() method of the Greeting interface.

--This is Target Typing.

Method Reference
=================


--It is the simplified form (short-cut) of Lambda Expression (Cleaner alternative).

--Instead of creating a Lambda Expression with all the details, With the help of Method Reference we can refer an existing class method to the functional interface variable.

--It is represented by using :: double colon symbol.



Many developers write:

	name -> System.out.println(name)

But experienced Java developers usually write:

	System.out::println

--This is called a Method Reference.



--Method reference works only when the method signature matches the functional interface method.


Types of Method Reference:


| Type            | Syntax                |
| --------------- | --------------------- |
| Static method   | ClassName::methodName |
| Instance method | object::methodName    |--Bounded type
| Constructor     | ClassName::new        |

Unbound Instance Method Reference:
---------------------------------

--Sometimes we do not refer to a method of a specific object. Instead, we refer to an instance method of a class itself.

--Not bounded with any specific object, instead take the parameter of any object of the class.



Example:

@FunctionalInterface
interface NameIntr {
    String convert(String name);
}



public class Demo {

    public static void main(String[] args) {

        // Using Lambda Expression
        NameIntr i1 = s -> s.toUpperCase();

        // Using Method Reference
        NameIntr i2 = String::toUpperCase;

        System.out.println(i1.convert("ratan"));
        System.out.println(i2.convert("kumar"));
    }
}



Output:

RATAN
KUMAR

How it works:

String::toUpperCase

is equivalent to:


s -> s.toUpperCase()


--Here Java automatically treats the first parameter of the functional interface method as the object on which toUpperCase() will be called.


i2.convert("kumar")

becomes:

"kumar".toUpperCase()



Note: This type of method reference is called an "Unbound Instance Method Reference" because we are referring to an instance method of a class without creating or specifying a particular object.


--On which object of String class the toUpperCase() method will be called will act as a parameter of the convert() method of NameIntr interface.

--And since the return type of convert() method is String and toUpperCase() also return String then it will be matched. 




In other word:



--The first parameter of the functional interface method becomes the object on which the instance method is invoked.

--And the return type of the functional interface method must match the return type of the referred instance method.

--Therefore:

String getStudentName(Student student);

matches with:

String s3.getName();


Student::getName;


because:

Input  : Student
Output : String

matches

Student -> String

1.Predicate<T>:
===============

--In this interface only one abstract method is there:


interface Predicate<T>{

	public boolean test(T t);

}


----The test(T t) method checks whether the supplied object satisfies a condition or not.

--A Predicate always answers only one question:

TRUE
or
FALSE



Examples:

--Is age greater than 18?

--Is salary greater than 50000?

--Is email valid?

--Is student passed?


Whenever your logic returns a boolean result,

Java says: Use Predicate.



Example1: 


PositivePredicate.java:
-----------------------

import java.util.function.Predicate;

public class PositivePredicate implements Predicate<Integer>{

	@Override
	public boolean test(Integer i) {
		
		if(i >= 0)
			return true;
		else
			return false;


		// return i >=0;	
	}
}

---------

		System.out.println(isEven.test(10)); //true


		//To check a valid Email address

	}

5. BiFunction<T,U,R>
=====================


--This interface is derived from Function interface. or we can say that it is the another varient of the Function interface.


--As we know that a normal Function takes one input and one output:

Function<T, R>

--But if we need 2 input and 1 output then we need to use:

BiFunction<T, U, R>

--Take Two Inputs, Transform Them, Return One Result


public interface BiFunction<T,U,R>{

    R apply(T t, U u);

}



Example 1: Add Two Numbers

Input1 : 10
Input2 : 20

Output : 30


Example 2: Create Full Name

Input1 : Raj
Input2 : Kumar

Output : Raj Kumar


Whenever You Need

Take Two Inputs
Perform Some Logic
Return Result


Use: BiFunction<T,U,R>


Where:

T = First Input Type
U = Second Input Type
R = Return Type

Comparator.comparing():
========================

The Problem Before Java 8

Suppose we want to sort students by marks.

--we can either make use of external class by implemeting the Comparator

or

--we can make use of annonymous inner class approach:

But after from Java 8 we can make use of Lambda expression:

students.sort( (s1,s2) -> Double.compare(s1.getMarks(),s2.getMarks()));


--But Java 8 provides an even cleaner approach using: Comparator.comparing()


--Comparator.comparing() is a static factory method of the Comparator interface that creates a Comparator based on a specific property (key) of an object.



public static Comparator comparing(Function<T,U> keyExtractor)


Here, keyExtractor

means:

--Which property should be used for sorting?

For marks:

Student::getMarks

For name: 

Student::getName

For Roll:

Student::getRoll


Example1: Soring by Marks


Using Lambda:

	students.sort( (s1,s2) -> Double.compare(s1.getMarks(),s2.getMarks()));

Using comparing():

	students.sort(Comparator.comparing(Student::getMarks));

Much cleaner.


means:

For every Student object,

extract the marks

and compare those marks.



Example 2: Sort By Name


Using Lambda:

	students.sort((s1,s2) -> s1.getName().compareTo(s2.getName()));

Using comparing():

	students.sort(Comparator.comparing(Student::getName));


Note: comparing() does NOT sort.

It only creates a Comparator.

Actual sorting is done by:

Collections.sort()

or

List.sort()



Example:

Comparator<Student> cmp = Comparator.comparing(Student::getMarks);

students.sort(cmp);


thenComparing():
----------------

--Using this method we can chain the comparaing() methods.

For Examaple: If the 2 students marks are same them sort them using their name:


Using Lambda:

students.sort((s1,s2)->{

    int result = Double.compare(s1.getMarks(),s2.getMarks());

    if(result == 0) {
        return s1.getName().compareTo(s2.getName());
    }

    return result;

}); 


--Too much code:


Using thenComparing():


students.sort(Comparator.comparing(Student::getMarks).thenComparing(Student::getName));


Multiple thenComparing():

--We can keep chaining.


students.sort(Comparator.comparing(Student::getMarks)
    						.thenComparing(Student::getName)
    						.thenComparing(Student::getRoll));


reversed():
-----------

students.sort(Comparator.comparing(Student::getName));

--It bydefault using Ascending order, to make it in descending order:

students.sort(Comparator.comparing(Student::getName).reversed());


Example: Sort By Marks Descending If Marks Same Sort By Name in ascending order:


students.sort(Comparator.comparing(Student::getMarks)
						    .reversed()
    						    .thenComparing(Student::getName));







Note: When we use:

Comparator.comparing(Student::getRoll);

--here getRoll() method returns the primitive type: int

--Java internally converts it to Integer : Autoboxing, since Collection does not support the primitives.


--To avoid this unnecessary boxing:

Java provides:

Comparator.comparingInt(...)

Example:

students.sort(Comparator.comparingInt(Student::getRoll));


Similarly:

comparingLong()
comparingDouble()
--

--for better performace.

--It is recommended to use:

comparing(): for String comparison
comparingXXX(): for primitive types
